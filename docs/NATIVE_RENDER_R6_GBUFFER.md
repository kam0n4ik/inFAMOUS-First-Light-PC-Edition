# R6-G: G-buffer / Geometry Engine (ветка `feature/r6-gbuffer`)

Фаза R6 (docs/NATIVE_RENDER_R6_CORE.md), подсистема «геометрия»: основной цикл геометрического прохода движка
inFAMOUS Second Son и его вызовы отрисовки. Статусы — как в R5: ANALYZED (разобрано), GENERATED (код есть),
OFFLINE_VERIFIED (дифференциальные тесты против кода eboot), GAME_VERIFIED (verify в игре, 0 расхождений),
PERFORMANCE_VERIFIED (A/B с подтверждённым приростом). Генерация кода ≠ доказательство.

## 1. Функции

| eboot | наше имя | ключ | что делает | статус |
|---|---|---|---|---|
| 0x1a2030 | GBuffer::MeshPass | — | цикл прохода: сортированные объекты → материал (0x448640 при смене), объектные константы (0x11c890/0x11cde0), константы отрисовки (0x11e5d0/0x120280), записи инстансов 0xD4 (0x1f0870), вызов 0x1a1960 / 0x1a1770 | ANALYZED; recomp GENERATED (lift-check PASS) |
| 0x1a1770 | GBuffer::InstancedDraw | `gbuffer_instanced_draw` | стенсил (кэш R+0xde64), константы, V# формата вершин (0x45f590), V# записей инстансов, потоки вершин, NUM_INSTANCES, тип примитива/индексов, коммит CUE 0x14ad0, drawIndex | ручная: GAME_VERIFIED (verify, город); recomp: OFFLINE_VERIFIED |
| 0x1a1960 | GBuffer::MeshDraw | `gbuffer_mesh_draw` | потоки вершин (со скиннингом: копия таблицы V# на стек с подменой до 3 потоков), V# скина/умолчаний, доп. поток материала, тип примитива/индексов, коммит CUE, drawIndex | ручная: GAME_VERIFIED (verify, город); recomp: OFFLINE_VERIFIED |

Семантика с адресами полей — в шапке `src/native_engine/reconstructed/gbuffer_draw.h`.

Особенность 0x45f590 (V# формата вершин): при нулевом элементе таблицы eboot+0x7dff738 функция возвращает в RAX
значение stack guard, а в RDX — то, что оставил вызывающий (мусор). Это не воспроизводимо побайтно; ручная реализация
такие вызовы не исполняет сама — зовёт оригинал (счётчик `unfollowed` в замерах). То же для 0x1a1960 при >32 потоках
или индексе скина вне стековой копии (там оригинал пишет за пределы своего буфера; генераторы тестов такие случаи не
создают — исполняется код eboot).

## 2. Как проверяется

Обе функции — «оркестраторы»: почти всё, что они делают, — вызовы с побочными эффектами (пакеты DCB, аллокации кольца,
состояние CUE). Проверка по вызовам (`gbuffer_trace.{h,cpp}`):
- оригинал исполняется как клон (guest_code_clone.h), чьи вызовы записываемых функций уходят в thunk-и (xbyak):
  thunk сохраняет RDI..R11 и XMM0–15, пишет вызов (регистры аргументов, байты по указателям — V# по 16 байт × count),
  возвращает значение «эффекта» (CUE-сеттеры — свой CUE; 0x45f590 — детерминированная последовательность в RAX:RDX;
  memmove — выполняется) и восстанавливает все регистры;
- реализация (ручная — таблица вызываемых на thunk-и; recomp — `recomp_set_redirects`) — на тех же входах, на
  теневом контексте (своя копия R, в неё скопирован u32 стенсила R+0xde64);
- сравниваются: порядок вызовов, объявленные аргументы (указатели в теневой R — как смещение, в стек — как «стек»),
  байты по указателям, итоговое состояние стенсила. Для ручной реализации 32-битные аргументы сравниваются по младшей
  половине (оригинал оставляет мусор в старшей), для recomp — целиком.
- Не перехватываются (исполняются по-настоящему в обоих прогонах, закреплены хешем в `assumed`): 0x61e260/0x61f430
  (V# буфера записей), 0x27530 (номер стадии), 0x61e030.
- GOT-слоты, которые функции читают (stack guard 0xd9de00, глобал умолчаний 0xd9dec8) и два элемента таблицы
  форматов, в окне загрузчика нулевые: на время self-check/тестов `GotForChecks` ставит временные значения и
  восстанавливает их.

Режимы реестра: verify (сравнение каждого вызова, исполняется оригинал), guarded (сравнение каждого N-го, при
расхождении — откат на оригинал до конца сессии), native, bench (оригинал со счётчиком). Оба ключа — `explicit_only`
до GAME_VERIFIED: в «все функции» не входят.

## 4. Игра

Город, пресет стенда (`SSPC_CITY_PERFORMANCE=1`: CITY-OPT Phase 5/6 с G-buffer runs), обе функции установлены **под
entry-probe CITY-OPT** (лог: «below the entry probe already on it»).

- `r6g_verify1`: падение через 5 с при установке. Причина (доказана логом следующего прогона): GOT-слот 0xd9dec8 в окне
  загрузчика содержит не 0, а значение до релокации (0xf1bcd0), self-check 0x1a1960 читал через него. Исправлено
  (`32b15da`): на время проверки слоты подменяются всегда и восстанавливаются после.
- `r6g_verify2b` (verify обеих, 150 с): **0x1a1770 — 6 276 323 вызова, 0x1a1960 — 21 268 862; проверено всё, mismatches 0,
  skipped 0, fallbacks 0**; ошибок в логе 0. CITY-OPT: помечены все draw (mesh 22,1 млн из 22,1 млн, instanced 6,6 млн из
  6,6 млн, без хвостового NOP — 0), серии строятся (4,2 млн серий, 32,4 млн draw в них) — G4 не нарушен.
- `r6g_stats1b` (guarded обеих + `SSPC_R6G_STATS=1`): ручная реализация исполняет все вызовы (native 5,87 млн + 19,9 млн),
  выборочных сравнений 22 912 + 77 809, mismatches 0, fallbacks 0; ошибок в логе 0.
- FPS этих двух прогонов не сравнивается: разные режимы (verify / guarded + замеры), по одному прогону — это не A/B.

Выводы:
- Движок уже не делает лишнего на уровне вызовов: материал, стенсил, константы отрисовки и объекта — только при смене.
- Таблица VS 0x1a1770 меняется каждый раз (новый V# записей инстансов в каждом вызове) — её копия не избыточна.
- **~890 PS-коммитов и ~380 VS-коммитов на кадр копируют таблицу, побайтно равную предыдущей** (в основном 0x1a1960:
  52 % грязных PS-коммитов). Это совпадает с оценкой R6-P (~1 000 лишних обходов SRT/кадр ≈ 1,3 мс потока 1) — цифры
  для дедупликации копии таблиц CUE. Эту работу (зона 0x14ad0) взял R6-Core; в R6-G она не делается.

`SSPC_R6G_STATS=1` (с native/guarded ручной реализации): на вызов — такты всего вызова, коммита CUE и drawIndex,
дворды DCB, записи стенсила, коммиты констант отрисовки, пути (V# формата, скин, умолчания, доп. поток),
непокрытые вызовы; на коммит — какие стадии CUE грязные (VS/PS таблицы, шейдеры, прочие стадии), размер таблиц,
совпадает ли таблица стадии с предыдущей закоммиченной (этот поток, тот же CUE), сколько 16-байтных слотов
изменилось. Отчёт `r6g stats/10s` каждые 10 с.

## 6. Оптимизации (G3)

Принятых нет. Главный кандидат по замерам (повторное использование копии таблицы стадии CUE) — у R6-Core.
Перенос той же работы в нативный код прироста не даёт (R5; оценка R6-Core по мосту P5.3).

## 7. Ограничения

- Проверка по вызовам не исполняет вызываемые функции в проверочных прогонах: их правильность — предмет их
  собственных реконструкций (0x14ad0 cue_commit, 0x16aa0/0x16b70 — R5-C/D).
- Ветка 0x45f590 с нулевым элементом таблицы — не воспроизводится, исполняется оригинал.

## 8. Коммиты

- `3214b30` [shared] тесты: проверка числа функций реестра 11..kMaxFunctions.
- `0213abd` R6-G: 0x1a1770 / 0x1a1960, запись трасс, тесты, документ.
- `32b15da` R6-G: self-check подменяет GOT-слоты независимо от их значения.
- `7b0f335` cherry-pick [shared] исправления стенда R6-Core (`3b9730a`).
