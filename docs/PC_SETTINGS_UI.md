# PC Settings UI — окно настроек SecondSonPC (редизайн)

Ветка `feature/pc-settings-redesign` (worktree `E:\SecondSonPC-settings-ui`), база `04a6d22` (main). Документ
описывает **текущее** окно дополнительных настроек PC Edition; история прежних вариантов — в
`docs/PC_SETTINGS_IMPLEMENTATION.md` (меню F1, октябрь 2026) и `docs/PC_EDITION_UI.md` (страница «под игру», 16.10).

## 1. Где реализовано и как вызывается

| Часть | Файл | Что делает |
|---|---|---|
| Пункт в меню игры | `src/runtime/filesystem/content_patch.cpp` | строки «HDR Rendering — Unavailable» таблицы языка заменяются при чтении на «Дополнительные настройки — Нажмите ⊗» (файлы игры не меняются) |
| Какой экран игры открыт | `src/engine/ui/game_menu.cpp` | зонды на `0x27db10` / `0x27e210` (экраны паузы); экран «Настройки» — вид 7 |
| Какой пункт выбран | `src/runtime/gpu/menu_focus.cpp` | две узкие полосы показанного кадра (жёлтая строка, ползунок списка) |
| Хост окна | `src/ui/menu_controller.cpp` | ввод (клавиатура/мышь/геймпад), открытие/закрытие, окружение (`MenuEnv`), применение окна/ввода/геймпада |
| Модель и вёрстка | `src/ui/settings_menu.{h,cpp}` | разделы, строки, фокус, правка значений, списки, подтверждения, вёрстка в `DrawList` |
| Отрисовка | `src/ui/overlay_win32.{h,cpp}` | два layered-окна поверх окна игры (затемнение + панель), Direct2D **software** + DirectWrite, без GPU |
| Реестр настроек | `src/settings/registry.cpp` | одна таблица: ключ TOML, тип, диапазон, как применяется, какие возможности нужны, подписи RU/EN |
| Хранение | `src/settings/settings_service.cpp`, `user_store.cpp` | `SecondSonPC.toml` = умолчания; `%LOCALAPPDATA%\SecondSonPC\settings.toml` = изменения пользователя |
| Применение в мосте/бэкенде | `src/bridge/shadps4/settings_host.cpp`, `bootstrap.cpp` | громкость, FPS-счётчик, лимит FPS, апскейлинг, генерация кадров, частицы |

**Вызов (не менялся, найден в коде):** во время игры Esc (Options на геймпаде) → экран игры «Настройки» →
последний пункт **«Дополнительные настройки — Нажмите ⊗»** → ✕ (Пробел — клавиша действия «Крест», ✕ на
геймпаде с учётом `[System] enterButton`) или щелчок мышью по пункту. Дополнительно (выключено по умолчанию):
`[Gamepad] menuButton = "guide" | "l3r3"`; для разработки — F1 при `SSPC_DEV_F1=1`. Старое меню F1 удалено ранее
(`303ee44`) и не восстанавливалось.

**Закрытие:** Esc / ○ (или ✕ при `enterButton = "circle"`) на верхнем уровне, правая кнопка мыши, кнопки ✕ в
заголовке и «Закрыть» внизу, Options/Start/Guide на геймпаде. После закрытия на экране снова «Настройки» игры,
курсор свободен (экран паузы), при выходе из паузы захватывается снова; удерживаемая кнопка контроллера не доходит
до игры, пока её не отпустят.

## 2. Структура окна

```
┌────────────────────────────────────────────────────────────────────────────┐
│ НАСТРОЙКИ [PC EDITION]                     (⟳ Нужен перезапуск: N)    [✕]  │ 60
├──────────────┬─────────────────────────────────────────────────────────────┤
│ ▣ Графика    │ ГРАФИКА                                                      │
│ ▭ Экран      │ МАСШТАБИРОВАНИЕ ───────────────────────────────────          │
│ ◎ Управление │ ▌Технология масштабирования        [ NVIDIA DLSS        v ]  │ строки 40
│ ⌨ Клавиши    │  Качество                           [ Качество (1280×720)v ] │
│ ◁ Звук       │  Резкость изображения     ━━━━━━●──────────  [ 30 % ]        │
│ ▢ Игра       │  ...                                                    ▐    │ полоса прокрутки
│ ⚌ Дополнит.  ├─────────────────────────────────────────────────────────────┤
│              │ (статус последнего действия)                                 │ 96
│ Изменения    │ Описание выбранного пункта, причина недоступности, «сейчас  │
│ сохраняются  │ действует: … — после перезапуска»                            │
├──────────────┴─────────────────────────────────────────────────────────────┤
│ [↑↓] Выбор [←→] Изменить [Enter] Открыть [Tab] Раздел [Del] Сброс   [Закрыть]│ 52
└────────────────────────────────────────────────────────────────────────────┘
                                 900 × 700 (единицы вёрстки)
```

- Размер окна **одинаков для всех разделов**: 900 × 700 единиц; при 1920×1080 и масштабе Windows 100 % это 900 × 700
  пикселей по центру. Масштаб = max(высота окна / 1080, масштаб DPI окна) × `[Interface] scale`, затем — сколько
  помещается в окно игры с полем 12 px; минимум 0,35. На малых окнах всё уменьшается целиком, список прокручивается
  внутри; ничего не выходит за окно игры (проверка вёрстки в самотестах — 720p, 1080p, 1440p, 4K, 21:9, 4:3, 800×600).
- Сцена видна на фоне: остальная часть окна игры затемняется постоянной альфой 110/255 (одна заливка, без размытия).
- Стиль — меню inFAMOUS: Second Son: тёмная полупрозрачная панель, тонкая белая рамка с угловым квадратом и
  «язычком» сверху, жёлтый цвет игры для выбранного, заголовки — Roboto Slab заглавными (как в игре), пункты —
  Roboto Condensed (`assets/fonts`; без них — Bahnschrift/Segoe UI). Скругления 3–6 px.
- Иконки разделов, галочки, стрелки списков, круговая стрелка перезапуска, ✕ — векторные (линии, круги,
  треугольники `DrawList`), не шрифтовые и не эмодзи; подсказки кнопок — клавиши, фигуры PlayStation (✕○□△
  нарисованы примитивами) или буквы Xbox, по последнему устройству.
- Анимации: окно проявляется за ~60 мс (меняется только непрозрачность уже нарисованного слоя, без перерисовки).

Неактивные состояния: серый текст строки — пункт сейчас не действует (зависит от другого: «Действует, когда
включено …», «Работает с DLSS или FSR», размер окна при полноэкранном режиме) — значение можно менять заранее;
«Недоступно» — пункт этого запуска нет (нужен другой бэкенд/оборудование), изменить нельзя, причина в описании.
Значение, которое система не может выполнить (например, DLSS в файле на видеокарте без RTX), показывается
красным с причиной; в списках такие варианты серые с пометкой «недоступно».

Сохранение: каждое изменение сразу записывается в `%LOCALAPPDATA%\SecondSonPC\settings.toml` (`[Таблица] ключ`, те
же ключи, что в `SecondSonPC.toml`), в фоне (поток записи, пауза 250 мс объединяет серию — ползунок пишется один
раз), атомарно (`.tmp` → замена, прежняя версия — `.bak`; нечитаемый файл не перезаписывается, битый — уходит в
`.corrupt-<время>`). Значение, равное умолчанию, из файла удаляется.

**Не показываются** (в реестре как `Apply::Unavailable`, ничего не хранят): разрешение рендеринга (задаётся
качеством апскейлера), качество текстур, анизотропия, тени, эффекты, сглаживание, размытие в движении, глубина
резкости, выходное разрешение выше 1920×1080 — не реализованы. DLSS Frame Generation и множитель ×3/×4 — в сборке нет
(возможность `DlssFrameGen` никогда не выставляется), не предлагаются. Строки FSR 1.0/RCAS презентера моста — только
при `--gpu-backend bridge`. Экспериментальные переменные `SSPC_*` и отладочные флаги в окне не показываются.

## 5. Правила сохранения и совместимость

- Один источник: реестр (`registry.cpp`). Новой системы конфигурации нет; меню, файл и самотесты работают от него.
- `SecondSonPC.toml` окно не пишет (умолчания, строгий разбор при старте).
- **Неизвестные ключи пользовательского файла сохраняются** (новое): ключ, которого эта версия не знает (из более
  новой версии или дописанный вручную), значение неверного типа/диапазона, ключ недоступной настройки — не
  используются, но записываются обратно при каждом сохранении в свои таблицы (`KeptKeys`, `user_store.h`).
  Если пользователь меняет в окне настройку с таким ключом, новая строка заменяет старую. Раньше такие ключи
  терялись при первом же сохранении.
- Отклонение неподдерживаемого: тип/диапазон проверяются при чтении и при изменении (`Validate`), недоступная
  настройка не меняется (`SetResult::Unavailable`), варианты выбора, которые система не выполнит, не выбираются.
- Экран (полный экран, тип, размер окна, монитор): после изменения — диалог «Оставить новые параметры экрана?» с
  обратным отсчётом 15 с и полосой; без ответа, по «Вернуть», по Esc или при закрытии окна — прежние значения.
- Закрытие окна с открытым списком — ничего не выбирается; с открытым диалогом экрана — откат.
- Раздел и выбранный пункт запоминаются на время сеанса (следующее открытие — там же).

## 6. Графические параметры (особенности)

- Апскейлинг и генерация кадров есть только у собственного бэкенда (`--gpu-backend sspc`, по умолчанию).
  Смена технологии/качества/генерации — сразу: `Gpu::Upscale::ApplyConfig` + `Bridge::ApplyUpscaling` (размер
  рендера переключается на следующем кадре игры, FSR FG заменяет swapchain). Резкость и Reflex — сразу.
- Доступность по оборудованию берётся у работающего бэкенда: `Capability::Dlss` (NGX + RTX), `FsrFrameGen`,
  `Reflex`; причины — из `Gpu::Upscale::Status` (`dlss_why`, `fsr_fg_why`), FSR 3.1 — по наличию
  `amd_fidelityfx_vk.dll` рядом с exe (как проверяет `ApplyUpscaling`). Если выбранный апскейлер не запустился,
  в описании «Сейчас не работает: …» (`Status::reason`).
- «Разрешение рендеринга» — информационная строка, фактический размер сцены (`Upscale::GetRenderSize`).
- Генерация кадров без апскейлера не работает (нужны его глубина и векторы движения) — строка серая с пояснением.
- **Счётчик FPS теперь работает и на собственном бэкенде** (раньше там был всегда включён и не управлялся):
  `[Display] showFps` → `Gpu::Native::SetFpsCounter` → флаг презентера (`Vk::SetFpsCounterShown`, атомик, читается
  при показе кадра); F10 переключает настройку на обоих бэкендах. `SSPC_FPS_OVERLAY=0` по-прежнему скрывает.

## 7. Управление окном

Клавиатура: ↑/↓ (и W/S) — пункт; ←/→ (A/D) — значение; Enter/Пробел — открыть/переключить/назначить; Esc — назад
(список → диалог → окно); Tab/Shift+Tab, Q/E — раздел; PageUp/PageDown; Del — пункт по умолчанию; Backspace —
очистить ячейку клавиши. Мышь: наведение выбирает пункт (описание внизу следует за ним), щелчок, перетаскивание
ползунков и полосы прокрутки, колесо, правая кнопка — назад. Геймпад: крестовина и левый стик (с автоповтором 400/110 мс),

## 10. Ограничения

- Раздел и пункт запоминаются только на время сеанса; после перезапуска окно открывается на «Графике».
- На окнах игры высотой от 700 px окно не уменьшается ниже 100 % масштаба Windows, чтобы текст оставался читаемым:
  при 1600×900 оно занимает 900×700 пикселей. При высоте меньше 700 px оно уменьшается целиком (минимум 0,35).
- Отрисовка идёт через Direct2D software на CPU: 6–9 мс на кадр окна при 1080p, 15–20 мс при 4K. Но только по
  событиям и не в потоке игры.
- Настроек, которых нет в движке/бэкенде (качество текстур, тени, сглаживание, размытие в движении, разрешение
  выше 1920×1080, DLSS Frame Generation), в окне нет: они не реализованы, а не скрыты.
- Применение экрана (полный экран, размер, монитор) и пресеты размеров работают как раньше в `menu_controller.cpp`
  (SDL); список размеров ограничен рабочей областью монитора.
- Звук: «Общая громкость» и «Устройство вывода» работают только с аудиовыводом моста (SDL). С `--native audio` они
  помечены «Недоступно» с причиной.
- Вертикальная синхронизация, устройство звука, язык игры, кнопка подтверждения и параметры кэша шейдеров
  применяются после перезапуска (так устроены подсистемы), и окно об этом говорит.
- Геймпад в реальной игре не проверялся.
