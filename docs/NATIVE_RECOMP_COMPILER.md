# Статический рекомпилятор функций движка (R5)

Часть Native Engine Reconstruction (`docs/NATIVE_ENGINE_RECONSTRUCTION.md`). Переводит отдельные функции eboot
(x86-64 System V, AVX) в C++, который собирает clang-cl, и ставит результат вместо оригинала через существующий
реестр (`SSPC_NATIVE_ENGINE*`). Сгенерированный код выведен из кода игры и **в репозиторий не коммитится**: он живёт
в `E:\research\native-r5\recomp*` (вне дерева) и пересоздаётся из `pcode.json` командами ниже.

## 1. Конвейер

## 2. Модель исполнения

- **Регистры** — байтовый массив `R[]` в раскладке Ghidra, упакованный по диапазонам, которые функция называет
  (подрегистры EAX/AX/AL, XMMn_Da остаются псевдонимами, как в железе); временные SLEIGH (`unique`) — `U[]`, упакованный
  так же. Кадр — сотни байт (`0x11c890`: R 960, U 752, приватный стек 112), гостевые стеки малы.
- **Память** — гостевая (адрес гостя = адрес хоста); абсолютные и RIP-относительные операнды Ghidra отсчитаны от 0,
  к ним прибавляется `recomp_image_base` (ставят установщик и тестер).
- **Значения** до 8 байт — `u64`, шире — `V<N>` (XMM/YMM/ZMM); 16-байтовые целые (`MUL/DIV r64`) — `__int128`, деление
  — инструкцией `div/idiv` с ловушкой там, где железо дало бы #DE.
- **Плавающая точка** — те же инструкции процессора (`vaddss/vmulps/vucomiss/vcvt*`…) во встроенном ассемблере с
  `{vex3}` и порядком операндов оригинала, на текущем MXCSR потока: NaN-payload, знак нуля, округление, FTZ/DAZ,
  приближения `vrsqrtps/vrcpps` — аппаратные, как у оригинала. Полосовые операции P-code одной упакованной инструкции
  сливаются обратно в неё (`0x11c890`: 48 слияний). `-ffp-contract=off`, без fast-math.
- **AVX-операции**, оставленные SLEIGH как CALLOTHER (`vcmpps`, `vblendps`, `vpblendw`, `vhaddps`, `vpermilps`,
  `vinsertps`, `vmovmskps`, `vshufps`, `vunpck*`, `vrsqrtps`, `vrcpps`, …) — та же инструкция в регистровой форме;
  особые случаи: `vinsertps` с памятью (imm[7:6] игнорируются), `vmovlps/vmovhps`, `vpermilps` с imm и с вектором,
  `vmovmskps` → GPR. Неизвестная CALLOTHER — отказ.
- **Атомики** — `LOCK CMPXCHG` → один `__atomic_compare_exchange_n` (SLEIGH поднимает load/compare/store между
  маркерами LOCK/UNLOCK).
- **ABI.** Вход `recomp_<rva>` — голый переходник System V: RDI..R9, RAX (AL varargs), XMM0–7, указатель на стековые
  аргументы вызывающего; выход RAX, RDX, XMM0, XMM1. Тело работает на приватном стеке; сохраняемые регистры System V
  живут только в `R[]`. Глубина кадра и число стековых аргументов — анализ дельт RSP (включая форму `INT_ADD #d, RSP`
  с константой первой — без неё `0x11c890` читал бы неинициализированные аргументы); если адрес стека на уровне входа
  или выше уходит из-под анализа, копируется окно 256 байт.
- **Вызовы.** `CALL/CALLIND` — переходник `recomp_call`: RDI..R9, RAX, XMM0–7 и 32 слота стековых аргументов с
  приватного стека, обратно RAX, RDX, XMM0, XMM1. Затираемые вызываемым регистры (RCX, RSI, RDI, R8–R11, XMM2–15)
  после вызова сохраняют прежние значения, а не мусор вызываемого: корректный код их не читает (как и после любого
  компилятора). Переход на вход другой функции (`entries`) — хвостовой вызов. `BRANCHIND` — `switch` по целям Ghidra,
  чужая цель — ловушка; без целей — хвостовой вызов с ловушкой, если цель внутри тела.

### Семантические поправки к SLEIGH (найдены `--lift-check`)

| Что | SLEIGH | Железо | Поправка |
|---|---|---|---|
| Скалярные VEX `V{ADD,SUB,MUL,DIV,MIN,MAX,SQRT,RSQRT,RCP,ROUND}S{S,D}`, `VCVT{SI2SS,SI2SD,SS2SD,SD2SS}` с dst ≠ src1 или операндом в памяти (`0x11cce6 vmulss xmm0,xmm0,[m32]`) | `ZMMd = INT_ZEXT result` — биты 127:32 нули | биты 127:32 (127:64) из src1, 255:128 нули | генератор берёт src1[127:n] до инструкции и кладёт в dst после |
| AF у `ADD/SUB/CMP/INC/DEC/NEG` | не вычисляется (остаётся прежним) | определён | функция, читающая AF (`LAHF`, `PUSHF`…), — отказ; без читателя AF ненаблюдаем (флаги не входят в System V), `--lift-check` сравнивает AF только в функциях с читателем |

## 3. Классы пригодности

| Класс | Когда |
|---|---|
| SUPPORTED | функция переведена целиком |
| BLOCKED_BY_INSTRUCTION | неизвестная CALLOTHER, FLOAT_ROUND/CEIL/FLOOR, MXCSR как регистр, чтение AF, неожиданные размеры |
| BLOCKED_BY_CONTROL_FLOW | переход из тела не на вход функции, цель switch вне тела |
| BLOCKED_BY_ABI | динамический RSP (`and rsp,-16`, alloca), разная глубина стека на слиянии путей, запись в слот адреса возврата, > 256 байт стековых аргументов |
| BLOCKED_BY_MEMORY | сегменты fs/gs (TLS), прочие адресные пространства |
| BLOCKED_BY_EXTERNAL_CALL | вызов не в `ram` |

Отказ — всегда с причиной; неподдержанная инструкция не заменяется заглушкой. Классы PARTIALLY_SUPPORTED и
NEEDS_MANUAL_RECONSTRUCTION генератор не выдаёт: функция либо переведена целиком, либо отказана.

## 4. Проверка по инструкциям (`--lift-check`, `tools/native_engine_tests/lift_check.cpp`)

Для каждой поднятой отдельно инструкции (`lift_<addr>(R, U)`) N случайных состояний в каждом режиме MXCSR:

1. 15 GPR (RSP не операнд поднятых инструкций), CF PF AF ZF SF OF, YMM0–15: особые float/double (±0, денормали,
   ±inf, тихие и сигнальные NaN с payload, произвольные биты);
2. базовые и индексные регистры операндов памяти нацелены в буфер со случайным содержимым; RIP-относительные операнды —
   окно образа (снимок и восстановление);
3. процессор исполняет собственные байты инструкции в заглушке рядом с образом (±2 ГБ, RIP-смещение пересчитано); отказ
   (#DE, #GP выравнивания) ловится и должен совпасть с отказом подъёма;
4. подъём исполняется на том же состоянии с тем же аппаратным MXCSR;
5. сравниваются GPR, флаги (кроме undefined по Zydis и AF в функциях без читателя), YMM по 32 байта, память;
   биты статуса MXCSR — отдельно.

Режимы MXCSR: `0x1f80` (по умолчанию), `0x9fc0` (FTZ+DAZ), `0x3f80` (к −∞), `0x5f80` (к +∞), `0x7f80` (к нулю).

## 5. Проверка функций (`--recomp`)

- `recomp_1f0870`, `recomp_11c890` — дифференциальные тесты ручных реконструкций (миллион случаев, особые значения,
  NaN); `recomp_11c890` дополнительно по 250 000 случаев в каждом из четырёх нестандартных режимов MXCSR; вызов через
  гостеподобного вызывающего (сохраняемые регистры, RSP, DF, MXCSR); self-check установки.
- `recomp_11cde0`, `recomp_16aa0`, `recomp_16b70`, `recomp_120280` — оригинал и перевод на одних буферах
  (восстанавливаются между прогонами) через гостеподобного вызывающего; вызываемые функции (`0x626520`, `0x11be90`,
  `0x9843a0`, `0x11bed0`) в образе заменены записывающими заглушками: сравниваются вызовы (цель, переданные аргументы,
  16 байт V#-источника) и каждый байт памяти.
