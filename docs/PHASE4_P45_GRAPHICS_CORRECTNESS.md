### 4.1 Исправлено: записи CPU до пройденного WAIT_REG_MEM (R1)
Командный процессор теперь сообщает исполнителю о пройденном ожидании памяти (`GpuWork::MemoryAcquired`), бэкенд сливает
трекер записей CPU (`Backend::DrainCpuWrites`) до записи следующих команд. Прогон `p45_flicker4_fix`: 41 653 пройденных
ожидания, в **800** из них CPU успел записать отслеживаемую память — раньше эти draw читали старую копию. В паре
`p45_flicker3` (до) / `p45_flicker4_fix` (после) одиночная «вспышка» освещения при повороте камеры (кадр 1577: средняя
яркость 54,8 → 62,8 → 50,0, 28 блоков) не повторилась (n = 1 пара).

### 4.2 Исправлено: шкала GPU-часов (R10)

## 5. Освещение: нормали G-буфера (R15) — исправлено

Доказательства до правки: `logs\p45\ROOT_CAUSE_GBUFFER_R.md`.

- Цель: MRT1 G-буфера `0x2fa610000` (R16G16B16A16_UNORM, CB_COLOR_INFO 0x830 = 16_16_16_16 UNORM **ALT**), упакованная
  нормаль. R был 0 на 100 % пикселей; у моста — 0,49.
- SPIR-V не причина: мост (`--gpu-shader-capture`) и наш бэкенд дают **побайтно одинаковые** модули для тех же вариантов
  (PS 0x2dfc27f00 ×2, VS 0x2dfcc6800), байты runtime-параметров равны; `--gpu-shader-verify` 576/576.
- Этап потери (случай C — записан верно, затёрт позже): R = 0,4893 перед pipeline 277 и 0 после него; 277 (ps
  0x2edacb200, полноэкранный, маска 0x3) пишет в `frag_color1.x` константу 0,0 (`UnpackHalf2x16(0xFE000000)`).
- Причина: транслятор пишет компонент образа `i` из компонента экспорта `Map(i)` перестановки COMP_SWAP, а маска
  `CB_TARGET_MASK` (по компонентам экспорта) уходила в Vulkan без перестановки: для ALT маска 0x3 писала R,G вместо G,B.
  Мост: `swizzle.ApplyMask(mask)` (`vk_pipeline_cache.cpp:555`).
- Исправление: `ImageWriteMask(cb_info, mask)` в `BuildGraphicsPipelineState` (`pipeline_state.cpp`) — бит `i` образа
  включён, если включён бит `Map(i)` экспорта; для 4-компонентных STD/ALT/STD_REV совпадает с мостом. Действует для всех
  пайплайнов (статическая маска пайплайна и `vkCmdSetColorWriteMaskEXT`).
- Регрессия: самотест `Shader(runtime)` — 5 проверок (ALT 0x3→0x6, STD без изменений, STD_REV/ALT_REV, 16_16 ALT,
  состояние пайплайна целиком). Самотесты 1280/0.

| L6 | Тайловая запись переносила неинициализированные байты временного буфера в паддинг/промежутки | сначала детайлинг памяти гостя во временный буфер, затем копия образа, затем тайлинг |

Не исправлялось (сознательно, записано): L4 — одна точная запись CPU внутрь большого записанного GPU образа ведёт к
его перезагрузке из памяти целиком (поведение `RefreshImage` моста); L8 — unmap посреди draw выводит цель из поиска
(безопасно, вывод draw теряется); L9 — `DrainCpuWrites` на каждом пройденном WAIT берёт блокировку трекера
(производительность); L10 — диагностика (MSAA-чтение, деструктор `ImageReadback` без ожидания) — только при включённых
переключателях.

commit, повтор PASS, к GPU не относится); `p45_evict_validate3` (`=30`, валидация + sync): отброшено 4413, записано 12
(32 МиБ), **0 сообщений**, DEVICE_LOST 0; `p45_evict_all4` (`=1`) против обычного: flip 1000 — 7,81 % (пара обычных
7,70 %), flip 1800 — 26,6 % (пара обычных 50,9 %).

## 8. Производительность (P4.5.6): базовая линия и профиль, без оптимизации

Маршрут P4.4 (пляж, листва), 90 с, `--gpu-backend sspc`, без диагностики. Цель на потом — 60 FPS 1080p на Ryzen 5 5500 +
RTX 2060; в P4.5 скорость не оптимизировалась.

| Прогон | FPS листва (10-с окна) | Кадр командного процессора, мс (из них запись) | Простой CP, мс | GPU busy, мс |
|---|---|---|---|---|
| `p45_base_perf` (HEAD P4.4) | 16,1 / 16,9 | 43,8–45,8 (34,6–36,2) | 13,7–15,6 | 27,1 |
| `p45_wmask_perf` (после G-буфера) | 15,6 / 15,0 | 46,1–47,1 (36,5–37,5) | 16,5–18,0 | 28,9–30,5 |

Разброс одинаковых прогонов — ±1 FPS (`p45_flicker4_fix` 15,9/16,3, `p45_sync_before2` 16,9/16,8).

Разбивка записи кадра на листве (`p45_wmask_perf`, мс/кадр): frontend (программы, ресурсы, ключи) 12,3–12,6; привязка
ресурсов 8,3–8,4 (буферы 10,2–10,5 с учётом классификации); вершины/индексы 6,3–6,5; команды 5,6–5,9; dispatch целиком
5,1–5,2; барьеры/слои 1,0; 34–35 тыс. мелких диапазонов (≈ 33 МиБ) в кольцо на кадр. 88–90 тыс. draw/с.

Три главных ограничителя (по замерам, порядок — по влиянию на кадр):
1. **Однопоточный командный процессор** — запись ≈ 37 мс из ≈ 63 мс кадра (≈ 6 мкс на draw: frontend + привязка +
   вершины). Без распараллеливания/кэширования записи 60 FPS недостижимы (R13, P4.6).
2. **Сериализация CPU↔GPU**: игра держит один кадр в полёте и ждёт настоящего EOP (SSPC-018 п.5); простой CP с
   блокированным WAIT_REG_MEM — 16–18 мс/кадр. Кадр ≈ запись + ожидание GPU + ответ игры.
3. **GPU ≈ 29–30 мс/кадр** (RTX 2060): даже при бесплатном CPU потолок ≈ 33 FPS — нужны меньше глобальных барьеров
   (≈ 1 млн за прогон), без записи шейдеров в sparse-зеркало, профиль по проходам (`SSPC_GPU_PROFILE=1`).
