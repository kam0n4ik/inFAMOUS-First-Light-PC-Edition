здесь, кода нет; **[План]** — будущая фаза; **[Нельзя]** — решение «не делать».

## 2. Зависимости

```
SecondSonPC.toml ──LoadConfig (src\app\config.cpp)──► Config ──► мост (bootstrap.cpp: окно, present, звук)
                                                          └──► Input::Settings (src\input\settings.cpp)
SDL3 события окна ──► keyboard_mouse.cpp / motion.cpp ──► виртуальный геймпад ──► pad.cpp (scePad*, NATIVE) ──► игра
SDL3 геймпад DS4  ─────────────────────────────────────────► pad.cpp (слияние, R§1.4)
Игра: строки/глифы KCAP, иконочный шрифт lang_*_text.xpps (R§10) ──► подсказки (ПК-замена: §6)
Собственный бэкенд P4.4: presenter (vk_presenter.cpp) — будущая точка ПК-оверлея (§7)
```
Окно и presenter при `--gpu-backend sspc` — собственные (SDL-окно моста, swapchain SecondSonPC); ImGui моста там не
работает (патч 0032), поэтому ПК-оверлей для собственного бэкенда рисуется своим проходом презентера.

## 3. Клавиатура и мышь — [Реализовано]

- Действия: `Input::Action` (`src\input\settings.h`) — 16 кнопок DS4, 4 направления левого стика, ходьба (половина
  отклонения), и действия SecondSonPC: `ReleaseMouse`, `MotionMode` (контроллер «боком», мышь вращает — граффити),
  `Shake` (тряска баллончика), `TouchDrag` (мышь ведёт палец по тачпаду).
- Привязки: `[Keyboard] action = "Key"` или список; имена — SDL-скан-коды (не зависят от раскладки, русская
  включительно); `[]` — без привязки; разбор `ParseInput`/`InputName`. Shift+Tab не используется по умолчанию (оверлей
  Steam).
- Мышь → правый стик (`keyboard_mouse.cpp`, R§3.3): чувствительность, инверсия, `mouseDeadzone` — отклонение, с
  которого начинается движение (обход мёртвой зоны фильтра стика игры, R§3.1), захват курсора (Esc отдаёт).
- Ограничения сейчас: один контекст на всё (нет «меню/игра»), нет проверки конфликтов, профиль — только файл, нет
  накопления дробных смещений сверх кадра опроса, нет Raw Input (R§6).

## 4. Контракты — [Контракт]

### 4.1 Модель настроек
```
struct SettingDesc {           // один пункт ПК-настроек
    std::string_view id;       // "display.present_mode" — ключ раздела SecondSonPC.toml
    enum Type { Bool, Int, Float, Enum, Binding } type;
    range / enum values; default;
    enum Apply { Live, NextFrame, Restart, NotImplemented } apply;   // как применяется
    bool supported;            // false — пункт показывается серым с пояснением, без кнопки
};
class SettingsModel {          // владелец: приложение; читает/пишет SecondSonPC.toml
    Value Get(id) const; Result Set(id, Value);   // проверка диапазона, Apply
    std::span<const SettingDesc> Describe() const; // для меню и для --dump-settings
    Signal<id> changed;        // подписчики: окно, presenter, Input::Settings
};
```
Правило: пункт с `apply = NotImplemented` в интерфейсе не выглядит работающим (ТЗ: «НЕ показывать рабочую кнопку,
за которой ничего нет»). Сохранение — атомарная запись `SecondSonPC.toml` с сохранением комментариев (через
toml11), старый файл — `.bak`.

### 4.2 Карта действий с контекстами
```
enum class Context { Gameplay, Menu, Motion, TouchDrag };
struct Binding { InputCode code; Modifiers mods; };       // Ctrl/Alt/Shift
ActionMap: Context × Action → vector<Binding>; Conflicts(): пары с одинаковым Binding в одном контексте;
Active context: по состоянию ввода SecondSonPC (меню — пока игра в паузе по Options, R§14).
```
Конфликт в одном контексте — ошибка сохранения; одинаковая клавиша в разных контекстах — допустимо.

### 4.3 Поставщик подсказок
```
struct GlyphRequest { PadButton button; Context ctx; };    // что игра хочет показать (KCAP/иконочный шрифт, R§10.3)
GlyphProvider::Lookup(request) → { atlas rect | text label } для текущего устройства (клавиатура/мышь/DS4);
Device switching: гистерезис (R§12) — последний источник ввода, не дёргать при шуме стика.
```
Замена — наложение в рантайме на этапе вывода кадра/подмена глифа шрифта в памяти; оригинальные атласы и XPPS не
меняются [Нельзя: модификация файлов игры]. Строки локализации игры сохраняются.

## 5. DualShock 4 — тачпад двумя пальцами [План]

R§4: игра использует жесты тачпада (свайпы, нажатия, удержание; отдельные действия — поглощение сил, толкание машины —
требуют двух одновременных касаний; формат двух контактов подтверждён, R§4.2). Сейчас: одно касание (`TouchDrag`,
`touchPad` — палец в центре при нажатии). План: модель двух контактов в `pad.cpp` (ID, координаты, время), клавиатурные
макросы двух касаний (R§4.5), проверка на реальном DS4 — без физического контроллера тест не отмечается PASS
(R§4.9). Аналоги, триггеры, вибрация DS4 — сохранить (регрессионная проверка при любом изменении pad.cpp).

## 6. Подсказки клавиш [План]

R§10–11: источник подсказок — пакет KCAP и иконочный шрифт `lang_<язык>_text.xpps`; выбор — по устройству. Технический
путь: атлас глифов клавиатуры/мыши SecondSonPC (собственный, в ресурсах SecondSonPC) + подмена при выборе глифа
(R§11), автоматическое переключение по последнему устройству (R§12). Ничего из этого не реализовано.

## 7. ПК-меню и масштабирование [План]

- Точка встраивания: собственный презентер (`vk_presenter.cpp`) — отдельный проход поверх кадра игры (копия кадра в
  свой образ уже делается при flip). Вход — из паузы игры; пока меню открыто, ввод игре не идёт.
- Стиль: Windows-PC, тёмная тема, шрифт с кириллицей; масштаб UI по высоте окна: 1080p = 1,0; 1440p = 1,333; 2160p
  = 2,0 (кратно целым пикселям для иконок 16/24/32); минимальный кегль 14 px при 1,0.
- Раскладка: слева разделы (Экран, Графика, Звук, Управление, Клавиши, Геймпад), справа пункты из `SettingsModel`;
  «Применить/Отмена» для `Restart`-пунктов; сброс к умолчанию по разделу.
- Не делать до готовности GPU-пути: внутриигровое меню рисуется только собственным бэкендом; в пути моста — не
  встраивается (ImGui моста — временный).
