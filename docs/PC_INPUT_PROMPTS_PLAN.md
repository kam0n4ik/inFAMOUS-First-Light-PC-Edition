## 1. Что установлено

### Подсказки — это текст с «кнопочными» символами

- Строки интерфейса лежат в `art\cache\lang_<язык>_text.xpps` (пакет Sucker Punch, магия `KCAP`),
  **без сжатия**, UTF-8, парами `ключ\0значение\0`. Пример (русский):
  `u_hint_jump` → `Нажмите \xEF\x82\x83, чтобы подпрыгнуть`.
- Кнопка в строке — один символ из частной области Unicode (PUA): `\xEF\x82\x83` = **U+F083**.
  Русский пакет: 26 разных PUA-символов, 644 употребления; английский — те же коды.
- Сама игра хранит таблицу «кнопка → символ» ключами `u_button_*` / `u_btn_*`:

| Код | Кнопка PS4 | Источник | Сейчас на клавиатуре/мыши (`SecondSonPC.toml`) |
|---|---|---|---|
| U+F083 | ✕ | `u_button_x` | Space |
| U+F080 | ○ | `u_button_circle` | E |
| U+F081 | □ | `u_button_square` | V |
| U+F082 | △ | `u_button_triangle` | F |

### Иконки — растровые глифы отдельного «иконочного шрифта» в том же языковом пакете

- В `lang_russian_text.xpps` по смещению `0xdda50` — таблица глифов: записи по 32 байта
  (`u16` код, `u16` x, `u16` y, `u16` ширина, `u16` высота, 2 × `s16` смещения, `u16` шаг, …),
  58 глифов U+F080…U+F116. В английском пакете — по `0xbf570`, **записи иконок те же**.
- Ячейки атласа: ✕○□△ и крестовина 50×50; L1/L2/R1/R2/тачпад/стики 58×50; U+F095 (логотип на
  титуле) 256×211; служебные 17–32 px. Атлас ≈ 512 × 400 px.
- Где в пакете сама текстура атласа, её формат (A8/BC/RGBA) и тайлинг PS4 (GCN) — **не
  разобрано**. Имён ресурсов в пакетах нет (адресация без строк).
- `psarc` — только озвучка (`/dialogue/*.wem`); UI-пакеты `pulse.sprig.xpps`, `i3.sprig.xpps` таблицы
  кнопок не содержат.
- В GPU-мосте подмены текстур нет (детайлер есть: `video_core\texture_cache\tile_manager.cpp`).

### Русская локализация

Тот же механизм: русские строки содержат те же коды (`u_hint_jump` = «Нажмите U+F083, чтобы
подпрыгнуть»), иконочный шрифт — свой экземпляр в каждом языковом пакете с той же раскладкой.
Слова вокруг иконки («Нажмите», «Удерживайте») подходят и к клавишам — их менять не нужно.

## 3. Рекомендуемая архитектура

**Сейчас — вариант A, позже — B** (для смены устройства на лету), оба на одних компонентах:

1. `PromptCatalog` (`src\input\prompts\catalog.*`) — таблица выше: код PUA ↔ кнопка DualShock;
   источник истины — ключи `u_button_*` самой игры, проверяемые при старте (если в пакете ключ не
   совпал — подмена выключается, в лог — причина).
2. `PromptArt` — генератор ячеек 50×50 / 58×50 из раскладки `[Keyboard]`: клавиша в рамке
   («Space» → `␣`/«ПРОБЕЛ» мелким кеглем, буквы крупно, мышь — пиктограмма с подсвеченной
   кнопкой, стрелки — стрелки). Подписи — по языку `[Language]` («ЛКМ»/«LMB»).
3. `AtlasCodec` — чтение/запись текстуры атласа в её родном формате и тайлинге (сверка с
   детайлером моста; самотест «декодировал → закодировал → байты совпали»).
4. `AssetOverlay` (`src\runtime\filesystem\overlay.*`) — подмены диапазонов байт файла по
   (путь, SHA-256 оригинала): применяется в `read/pread` нативной файловой системы; при
   несовпадении хэша — ничего не меняет (другая версия игры). Оригинал на диске не меняется.
5. Конфиг: `[Input] prompts = "keyboard" | "gamepad" | "auto"` (`auto`: клавиатура, если при
   старте нет геймпада).

Точки интеграции: путь чтения файлов `src\runtime\filesystem\file_system.cpp` (игра читает пакеты
через Fios → наш `sceKernelOpen/Read`), таблица глифов ищется по сигнатуре (записи U+F080…F083 с
ожидаемыми размерами), а не по жёсткому смещению.

## 4. Ограничения

- Ячейка 50×50 (58×50) — длинные названия клавиш не помещаются: значки и короткие подписи;
  расширить ячейку можно, только переписав шаг глифа и найдя место в атласе (или в варианте B —
  новый атлас любого размера).
- Вариант A не переключает иконки при смене устройства в игре — только при старте.
- Подсказки внутри предзаписанных роликов (`.bsf`) не меняются.
- Неопределённые коды (U+F088, F08B, F08D, F0B5, F0B6) — сначала выяснить по игре.
- Комбинации (`L3+R3`, «Удерживайте») — текст игры уже это говорит, иконка — только одна клавиша.
- Читает ли игра пакет целиком при старте или кусками по ходу — **не проверено** (оверлей
  рассчитан на любые смещения чтения).

## 5. Пример реализации (эскиз)

```cpp
// src/runtime/filesystem/overlay.h — byte-range patches applied to reads of one game file.
struct OverlayPatch { u64 offset; std::vector<u8> bytes; };
struct OverlayFile {
    std::string guest_path;              // "/app0/art/cache/lang_russian_text.xpps"
    std::array<u8, 32> original_sha256;  // the patches apply only to this exact file
    std::vector<OverlayPatch> patches;   // sorted, non-overlapping
};
// In the native read path, after the host read of [pos, pos + n):
void ApplyOverlay(const OverlayFile& f, u64 pos, std::span<u8> data) {
    for (const auto& p : f.patches) {
        const u64 a = std::max(pos, p.offset), b = std::min(pos + data.size(), p.offset + p.bytes.size());
        if (a < b) std::memcpy(data.data() + (a - pos), p.bytes.data() + (a - p.offset), b - a);
    }
}
// Building it: locate the glyph table (code points U+F080..U+F083, 50x50 cells), locate and decode
// the atlas (AtlasCodec), draw PromptArt into the cells of the code points of PromptCatalog,
// encode, and diff against the original texture bytes -> patches.
```
