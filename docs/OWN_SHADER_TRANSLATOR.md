# Свой переводчик шейдеров GCN → SPIR-V

Свой код в `src/runtime/gpu/gcn` вместо переводчика моста (`third_party/shadPS4/src/shader_recompiler`). Он реализует
тот же интерфейс `Gpu::Shader::ShaderTranslator` (`src/runtime/gpu/shader/shader_translator.h`) и включается **по
программе**: что он переводит — его, остальное уходит мосту с записью причины в `logs\SecondSonPC.log`.

**С 2026-10-19 это переводчик по умолчанию** для CS, VS и PS (любой `play*.cmd`, `tools\run_phase0.ps1`). Мост — эталон для
A/B: `play_rea_bridge.cmd` (`SSPC_OWN_SHADERS=bridge`). Самотест (`--selftest`) без переменной проверяет адаптер моста.

Обозначения статуса в таблицах ниже:
* **Код** — реализовано.
* **Тест** — автоматическая проверка: офлайн-корпус `--gcn-translate-test`, самотесты.
* **val** — `spirv-val --target-env vulkan1.3` модулей из игры.
* **Игра** — подтверждено в настоящей игре. Где-то это сделал пользователь, где-то автоматический прогон со скриншотом;
  что именно, указано отдельно.
* **Огр.** — не проверено или ограничено.

## 2. Архитектура

```
GCN-код → gcn_decoder (инструкции, операнды) → gcn_cfg (граф) → gcn_structure (циклы, слияния)
        → gcn_resources (откуда SGPR: user data / SRT-обход / константы; V#, T#, S#; свой формат SRT-обхода)
        → gcn_emit (SPIR-V через spirv_builder) → gcn_translator (OwnTranslator: параметры стадии, отражение, отказ)
gcn_aux — вспомогательные стадии RECT/QUAD
```

* **Модель исполнения.**
  * Линия волны — это вызов SPIR-V. SGPR, VGPR, M0 и VCC — переменные функции.
  * 64-битная маска — это ballot подгруппы, бит линии — inverse ballot.
  * EXEC и SCC — булевы значения линии. Векторные участки выполняются под `if (exec)`, когда программа пишет EXEC.
  * Волна из 64 на подгруппах по 32 исполняется как отдельные волны по подгруппам.
* **Структура.** Заголовки и merge-блоки берутся из `gcn_structure`. Правки графа (`BuildGraph`):
  * свой merge-блок у вложенных if и у каждого цикла;
  * копия выходного блока `exp; s_endpgm` для каждого предшественника, если в него ведут несколько ранних выходов и он
    не служит merge;
  * у цикла из одного блока — свой continue-блок, потому что его код распадается на несколько SPIR-V-блоков.
* **Контракт с бэкендом** такой же, как у моста:
  * `PushData` (72 байта);
  * user data и копии SRT-обхода в буфере `Flatbuf`;
  * одна descriptor set, сквозная нумерация от `BindingStart` стадии: буферы (V#, Flatbuf, GDS, ClipPlanes), образы,
    семплеры;
  * отражение `ShaderReflection` того же состава.
* **Специализация.** Модуль зависит от того, что транслятор прочёл в момент перевода, и рантайм хранит это в ключе:
  * DATA/NUM_FORMAT и DST_SEL у V#;
  * тип и форматы T#;
  * FORCE_UNNORMALIZED и FORCE_DEGAMMA у S#;
  * dword 3 V# атрибутов вершин;
  * регистры стадии.

## 3. Стадии

### 3.1 Compute
* **Код:**
  * ALU, включая f64 и устаревшие mul/rcp;
  * SMRD, MUBUF/MTBUF (форматные, с точными невыровненными полями);
  * LDS, ds_swizzle, GDS append/consume;
  * образы: загрузка, запись, выборка;
  * id потоков и групп.
* **Тест:** корпус 7 934 из 7 934 валидны (включает и тестовую форму графических программ).
* **Игра:** 0 отказов на всех прогонах; проверено 10-18.

### 3.2 Vertex
* **Код:**
  * атрибуты fetch-шейдера — вершинные входы на location i, тип и чтение по V#, DST_SEL;
  * v0 = VertexIndex, v1–v3 — instance по VGPR_COMP_CNT и step rate, базы косвенных отрисовок;
  * POS0 → `gl_Position`; POS1–3 → точка, clip/cull по `PA_CL_VS_OUT_CNTL`; PARAMn → location n;
  * эпилог: z из [-w, w] в [0, w] без `depth_clip_control`; экранные координаты при CLIP_DISABLE.
* **Clip/UCP.**
  * Пользовательские плоскости (`PA_CL_CLIP_CNTL.UCP_ENA`) опускаются в расстояния `dot(pos, plane)` из буфера ClipPlanes,
    если программа не экспортирует свои. До `9f9ed2c` свой VS плоскости игнорировал.
  * На устройстве с эмуляцией (NVIDIA): расстояния 0–3 → vec4 на location 0, PARAM → n+1.
* **RECT/QUAD.**
  * Выходы те же, что для треугольников.
  * PointSize и RT/Viewport index не выводятся: как у моста, это должна делать последняя стадия перед растеризацией.
  * RECT-список рисуется в экранных координатах.
* **Игра:** G1-A подтверждён; RECT/QUAD — автоматический прогон (HUD, мини-карта, дым на месте).

### 3.3 Pixel
* **Входы.**
  * VGPR раскладываются по `SPI_PS_INPUT_ADDR`; позиция и front face берутся из ENA.
  * ANCILLARY = `SampleId << 8 | Layer << 16`.
  * Чтения регистра находятся анализом достижимости по блокам: запись, в том числе в VDATA загрузки, обрывает значение.
    Допускается только `v_bfe_u32` полей sample/layer, как у моста.
* **Интерполяция.**
  * Обычная: вход на `SPI_PS_INPUT_CNTL.OFFSET`; Flat, NoPerspective, Centroid, Sample — по тому, какие I/J читаются.
  * **Ручная (NVIDIA, как `needs_manual_interpolation` моста):** входы `PerVertexKHR`, I/J — y/z `BaryCoordKHR`
    (`InterpolateAtSample`/`Centroid` по виду барицентрик). p1/p2 вычисляют `P0 + I(P1−P0) + J(P2−P0)`.
  * Без ручной интерполяции PS `84a1d13b` (G-buffer) получал индекс 4.9999 вместо 5, отчего мерцал свет (исправлено в
    `4a60b8d`, подтверждено пользователем).
  * DEFAULT вместе с FLAT_SHADE — это вход, а не значение по умолчанию (`IsDefault` моста).
* **Экспорт.**
  * MRT по COMP_SWAP и `SPI_SHADER_COL_FORMAT`, распаковка сжатых экспортов, преобразования записи;
  * blend self-scale; MRTZ — глубина;
  * VM → demote неактивных линий.
* **Dual-source:** MRT1 с параметрами CB0 → location 0 index 1.
* **Clip-эмуляция:** входы на OFFSET+1, discard при отрицательном расстоянии (vec4 на location 0).
* **Ранние тесты:** EarlyFragmentTests при `DEPTH_BEFORE_SHADER`; DepthReplacing при экспорте глубины.
* **Игра:**
  * PS-часть подтверждена пользователем на `4a60b8d`: освещение, тени, мерцания нет.
  * `863d206` и `9f9ed2c` проверены автоматическими прогонами (скриншот, 0 сообщений валидации). Пользователь их ещё
    не смотрел.

### 3.4 Вспомогательные стадии RECT/QUAD (`gcn_aux`)
* **Код:**
  * RECT-TCS: четвёртый угол из трёх по признаку прямого угла, все варьинги интерполируются так же;
  * QUAD-TCS: порядок вершин 1, 2, 0, 3;
  * TES: угол `2v + u`;
  * варьинги на location `SPI_PS_INPUT_CNTL` фрагментной стадии.
* Отдаются `OwnTranslator::EmitAuxStage`, когда VS свои. `SSPC_OWN_SHADERS_DUMP=all` пишет `logs\own_aux_*.spv`.
* **Тест:** 6 из 6 (три стадии × без фрагментной стадии / с разными входами).
* **Игра:** QUAD — 10 модулей, валидны. **Огр.:** RECT в проверенной сцене не рисовался.

## 4. Текстуры и семплеры (G1-C)

**Код.**
* `image_sample`: неявный LOD (только во фрагменте) с bias и min-lod; `_l`, `_lz`; `_o`; `_c` (сравнение глубины).
* `image_gather4`: `_lz`, `_lz_o`, `_c`.
* `image_load`, `image_load_mip`, `image_store`.
* Координаты:
  * cube: AMD-координаты → 2D-массив граней, грань = `face − 2·floor(face/8)`;
  * ненормализованные делятся на размер уровня 0;
  * 1D — 2D-вид одной строки;
  * DA → массивный вид, как в рантайме (`ViewType`, `ConvertImageViewType`).
* Чтение:
  * числовой класс и преобразование по `RemapNumberFormat`/`MapNumberConversion` моста;
  * FORCE_DEGAMMA — gamma→linear сырого тексела, кроме sRGB;
  * результат сравнения — `(r, 0, 0, 0)`.
* Глубина:
  * изображение и семплер сравнения помечаются `is_depth` в отражении;
  * рантайм берёт вид D32/D16 и семплер с `compareEnable` и `DEPTH_COMPARE_FUNC` из S#;
  * семплер сравнения — отдельная запись, как у моста.
* Пустой T# (тип < 8) читается нулями (gather — четыре нуля), запись отбрасывается.

**Что встретилось в проверенных сценах** (`SSPC_OWN_SHADERS_DUMP=all` пишет T# и S# в `logs\own_*.txt`):
* типы: 1D, 2D, 3D, Cube (с DA и без), 1D- и 2D-массивы;
* форматы: BC1–BC6, 8/16/32 бит; UNORM, UINT, FLOAT, sRGB, UBNORM;
* глубина: D32 в 2D и 2D-массиве;
* семплеры: обычные; 9 с FORCE_DEGAMMA; 16 сравнения. Ненормализованных в сценах нет.

**Отказы (уходят мосту с причиной):**
* производные `image_sample_d`;
* gather с LOD ≠ 0;
* bias или LOD clamp при явном LOD;
* смещение при неявном LOD;
* смещение или ненормализованные координаты у cube;
* сравнение глубины на образе не float-класса;
* MSAA-образы;
* LOD storage-образа.

**Огр.** S#/T#/V#, которые программа собирает ALU-операциями над загруженным значением (шаблоны post-op моста:
`ConvertCubeTo2DArray`, `DisableAnisoIfSingleLod`, `ForceRepeatXyzClamp`, `ForceLastTexelXyClamp`,
`ClearAnisoRatioAndThreshold`, патч stride V#), не распознаются: анализ видит неизвестный dword и отдаёт программу мосту.
Поиск по всем пакам игры (`art\cache\*.xpps`, 26 ГБ):
* литералов шаблонов S# (`0xfffffe00`, `0xfff8f1ff`, `0xfffff1ff`, `s_bfe_u32 …, 0x0008000c`) — 0;
* литералов cube→2D-массив (`0x0fffffff`, `0xffffe000`) — 0;
* `s_getpc_b64` (inline-буфер констант, `OffsetByProgramBase`) — 1 программа из 10 301 (инвентарь);
* `s_or_b32` (возможный патч stride V#) — 2 программы.

Эти режимы поэтому не реализованы. Две-три программы с V#-шаблонами остаются мосту, если встретятся.

## 5. Отказ и диагностика

| Переменная | Что делает |
|---|---|
| `SSPC_OWN_SHADERS` | не задана — `cs,vs,ps` (по умолчанию); `cs,vs,ps` — любое подмножество; `bridge` — выключен, всё мосту |
| `SSPC_OWN_SHADERS_ONLY` / `_SKIP=<хеши>` | свои только эти программы / эти мосту (бисекция) |
| `SSPC_OWN_SHADERS_DUMP=all\|<хеши>` | `runtime\sspc\logs\own_{cs,vs,ps}_<хеш>.{txt,spv}`: код, V#, T#, S#, SPIR-V; `own_aux_*.spv` |
| `--gcn-translate-test` | весь корпус игры через тестовую форму + spirv-val; вспомогательные стадии (`logs\gcn_translate_test.txt`) |
| `--gpu-native-validate` | слой Vulkan Validation с Synchronization Validation (`logs\vk_validation.log`) |

* Отказ пишется в лог: `own GCN translator: <стадия> <хеш> to the bridge's (<причина>)`, первые 400 случаев.
* **Кэш:** у своего переводчика отдельная папка `cache\shaders\CUSA00004\native_own`. При смене поколения переводчика
  (`build\bin\own_translator_generation.txt`, хеш исходников `src/runtime/gpu/gcn`) или набора стадий она заново засевается
  из основной (`tools/seed_own_shader_cache.py`; его перед каждым запуском вызывают `tools\manual_run.ps1` и
  `tools\run_phase0.ps1`). С мостом (`bridge`) кэш — основная папка `native`. Модули этих стадий и их конвейеры при засеве выбрасываются, окно
  подготовки делает их своим переводчиком.

## 6. Известные ограничения и что осталось до отказа от shadPS4 в шейдерах

* Отказы из §4 и шаблоны post-op у дескрипторов. В проверенных сценах их нет; в других сценах игры возможны.
* RECT-список не проверен в игре; эмуляция clip несёт 4 расстояния, как у моста.
* Визуально подтверждены: свет и тени (пользователь), остальное — автоматические кадры одной сцены. Взрывы, бои, другие
  районы и прозрачность в других сценах отдельно не смотрелись.
* Мост остаётся:
  * запасным переводчиком;
  * в `CompareRuntime` (диагностика);
  * в поколении основного кэша;
  * эталоном для A/B (`play_rea_bridge.cmd`).
* До полного удаления зависимости в шейдерах нужно:
  1. прогнать остальные районы, бои и сюжетные сцены с `play_rea_own` и закрыть найденные отказы;
  2. распознать post-op дескрипторов;
  3. ~~сделать свой переводчик переводчиком по умолчанию, а мост оставить эталоном для A/B~~ — сделано 2026-10-19;
  4. убрать мост из `EmitAuxStage`/`CompareRuntime` и из поколения кэша.
