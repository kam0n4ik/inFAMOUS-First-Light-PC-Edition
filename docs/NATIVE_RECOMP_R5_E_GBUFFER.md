## 5. Проблемы генератора (предложения главному агенту для pcode2c.py)

1. **LEA RIP-relative не перебазируется** [E, v1: 28 инструкций]. В P-code `LEA RCX,[0xf1bcd0]` = `COPY RCX, const 0xf1bcd0`;
   генератор перебазирует только ram-варноды. Правка (локально применена): в `emit_ops` для `mnemonic == "LEA"` и текста
   `LEA r,[0x…]` запомнить цель; в `read()` 8-байтная константа, равная цели, → `(B + 0x…ull)`. Без неё recomp_1a2030/
   1a1770/1a1960 в игре читали бы данные по адресу без базы образа (краш). Тест: lift_1a20b7 должен давать image+0xf1bcd0.
   Отдельно: `lift_check.cpp` должен переадресовывать и AGEN (LEA) RIP-операнды в заглушке, иначе такие LEA всегда «FAIL».
2. **`AND RSP,-2^k`** (0x1a2030 @0x1a203d) → BLOCKED_BY_ABI. Правка: два прохода frame (пессимистичный rsp −(2^k−1)),
   глубина = max.
3. **Цели switch не получают глубину стека** (0x451440, 0x612150) → наследовать состояние BRANCHIND.
4. **Блок, достижимый только обратным переходом** (0x1a2030 @0x1a2eb7, переход из 0x1a3643) → «stack depth unknown».
   Правка: повторять линейный проход frame до неподвижной точки (≤256 раундов), отказ только если остались неизвестные.
5. **(V)CVTT?SS/SD2SI в 32-битный GPR** (0x45112b, 0x451261, 0x451269) — SLEIGH не обнуляет биты 63:32. Правка:
   после инструкции `st(R, rXX, 8, ld(R, rXX, 4))` + 64-битный регистр в layout. [E] v2: эти 3 расхождения ушли.
6. **IDIV r32**: лифт проверяет только деление на 0 и 64-битное переполнение; нужен #DE при частном вне int32.
7. **Мульти-переадресация**: `recomp_set_redirects(from[], to[], n)` (до 32, thread_local) — нужна для записи вызовов
   функций с многими callee (0x1a2030: 21). `recomp_set_redirect` совместим.
Diff всех правок: `E:\research\native-gbuffer\pcode2c_local.py` против исходного (SHA256 F1397B99…D628), бэкапы в
`E:\research\native-gbuffer\backup\`.

## 6. Совместимость с CITY-OPT [A]
0x1a1960 (всегда при CITY_ENGINE_OPT) и 0x1a1770 (при GBUFFER_RUNS/DIAG_ENGINE_SRT) — под входными пробами draw_runs:
прямой jump реестра не пройдёт хеш (безопасный отказ). Установку «под пробой» делает главный агент (ProbeRecord).
0x1a2030 и 0x11e5d0 проб не имеют; замена 0x1a2030 совместима с пробами: её вызовы 1a1770/1a1960 идут через гостевые входы.
