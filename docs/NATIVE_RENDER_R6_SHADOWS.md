## 2. Восстановление (S1)

### 2.1 `0x43d590` цикл теневых кастеров [A + E: OFFLINE_VERIFIED (перевод)]

Сигнатура SysV `(rdi param_1 = объект прохода, rsi param_2 = {gather, R, _, {lo,hi}})`, арность 4 (rdi,rsi,rcx —
rcx не используется, это артефакт live-in). Стековый кадр с `and rsp,-0x20` и `__stack_chk` (`0x984360`). Две ветви
по `param_1+0x1f` (без/с экземплярами) — анализ в R5-F §2, не повторяю.

**Статус генератора — SUPPORTED** (был `BLOCKED_BY_ABI` у R5-F). Проверено в `E:\research\r6\shadows\recomp`:
`pcode_dump.py` → `pcode2c.py` поднимает тело без отказа; `frame()` обрабатывает `and rsp,-0x20` двойным проходом
(сдвиг 0 и 2^k−1), глубина кадра — неподвижная точка по блокам. 16 вызываемых переводятся как `recomp_call`.

Побочные эффекты (по дизассемблеру, для будущей сверки) [A]:
- **ветвь без экземпляров**: пишет блок констант контекста `R+0xd190`/`R+0xd2f0` (через `0x11c890`/`0x11cde0`),
  копирует его в командный буфер по указателю `*[R+0xd2d0]`/`*[R+0xd370]` (ручной разворот `VMOVUPS`, 0x140/0x80 байт),
  сбрасывает флаги `[R+0xd2e8]`/`[R+0xd388]`; вызывает `0x448640`, `0x450460`, `0x120280`, `0x1a1960`, `0x16b70`,
  `0x61e260`, `0x612110`;
- **ветвь с экземплярами**: аллокация записей `0x1f0870(&DAT_00f1bcd0, n·0x48, 16)`, на объект 0x48 байт =
  матмул объект×VP каскада (`vpermilps`/`vmulps`/`vaddps`, строки 358–434 декомпиляции) + 8 байт нулей; вызывает
  `0x451700` (при `R+0x94>0`), `0x451290`, `0x448640`, `0x43d480`.

Офлайн-сверка `0x43d590` построена (S1b, §4.3): записывающий клон eboot и `recomp_43d590` на одном
сгенерированном мире; записываются 11 вызываемых, 4 исполняются по-настоящему; сравниваются вызовы, весь мир,
аллокации и состояние ГПСЧ. Статус — OFFLINE_VERIFIED для перевода (`recomp_43d590`); ручной реконструкции нет.

### 2.2 `0x43d480` теневой draw экземпляров [A + E: OFFLINE_VERIFIED (перевод)]

Оркестратор 11 вызовов Gnm/CUE (R5-F §3): `0x120280`, `0x61e260`, `0x27530`, `0x16b70`, `0x16aa0`, `0x6250b0`,
`0x623740`, `0x624f80`, `0x14ad0`, `0x623c60`. Своей арифметики нет. Генератор — SUPPORTED (74 инстр., 11 вызовов).
**Вход под пробой CITY-OPT** (`draw_runs`, `Source::Shadow=2`; при `SSPC_CITY_ENGINE_GBUFFER_RUNS=1` ещё и на
`0x448640`). Прямой jump ставить нельзя — интеграция только «под пробой» (`InstallFunction`/`InstalledBelowProbe`),
как у `0x448640` в R5-D. Офлайн — OFFLINE_VERIFIED (§4.2: записывающий клон, 9 целей). В реестр не интегрирован.

### 4.3 `0x43d590` [E]

Мир — один буфер 128 КБ: проход (флаги `+0x1f/+0x21`, записи `+0x90/+0x94`, флаги констант `+0x118/+0x11c`, слот
`+0x120`), аргумент `{R, сцена, _, lo|hi}`, контекст `R` (флаги блоков `+0xd2e8/+0xd388` во всех сочетаниях), сцена
(вид, массив элементов `+0x9b7·8`, ключи сортировки `+0x9b8·8` с группами экземпляров по старшим битам), 48 элементов,
по 8 объектов/мешей/материалов/буферов; порог отсева качества `0xda08d0[0xf39978]` — 0 или случайный, состояние ГПСЧ
`0x7f92020` — случайное. Флаги `0x11c890` без бита 3: `0x43d590` передаёт `extra = 0` (оригинал с битом 3 упал бы).

Записываются (эффекты): `0x11be90` (аллокация DCB из арены, указатель в `*dst`), `0x1f0870` (аллокация кадра; 1/16 —
null), `0x11bed0`, `0x120280`, `0x16b70` (+ 16 байт V#), `0x1a1960`, `0x43d480`, `0x448640`, `0x450460`, `0x451290`,
`0x451700`. Исполняются: `0x11c890`/`0x11cde0` (в образе тестов к этому моменту стоит проверенная ручная
`ObjectConstants` — одинаково для обеих сторон), `0x61e260`, `0x612110`.

| Режим MXCSR | Миров (с экземплярами) | Записанных вызовов | Различий |
|---|---|---|---|
| хост | 100 000 (40 607) | 2 503 475 | 0 |
| `0x9fc0` FTZ/DAZ | 25 000 (10 180) | 621 410 | 0 |
| `0x7f80` | 25 000 (10 110) | 627 870 | 0 |

Каждый записанный вызываемый достигнут (от 57 036 вызовов `0x451290` до 680 472 `0x11bed0`). Чувствительность: мир,
отличающийся на один байт (`+0x120` прохода) только для перевода, даёт различие в 318 из 1000 миров (ровно там, где
путь `+0x120` пройден). Весь набор: **256 проверок, 0 ошибок**.

Ограничения: миры сгенерированы (не снимки игры); вызываемые с побочными эффектами сверяются по аргументам, не
по своему действию (их собственная сверка — R5/R6-G/§4.2).

### 4.1 Ошибка SLEIGH `(V)PINSR*` (найдена `--lift-check`)

`0x450df8/0x450dfe/0x450e09 vpinsrd xmm0,xmm0,r32,imm` (1478–1495 из 1500 прогонов): подъём не вставлял dword.
P-code Ghidra считает 4 предиката `(imm&3)==k`, но во всех 4 группах выбора полос берёт предикат полосы 0 — при
`imm≠0` ни одна полоса не меняется. Ошибка спецификации SLEIGH (класс «скалярных VEX», `NATIVE_RECOMP_COMPILER.md`
§2), не генератора. Поправка `pcode2c.py pinsr_fix` ([shared]): в группе полосы `k` вход-предикат полосы 0 заменяется
на `k`-й. Репро — `E:\research\r6\shadows\generator_issues\vpinsr_lane_select.md`. Затронута только `0x450460`
(все 2654 поднятые инструкции проверены) — уже интегрированные функции R5 не задеты; поправка нужна любой будущей
функции с `pinsr*`. Без неё `recomp_450460` давал бы неверный результат при «зелёной» генерации — пример того,
почему GENERATED ≠ доказательство и `--lift-check` обязателен.

## 6. Ускорение (S2) — анализ

Профиль (R5-измерения, `NATIVE_ENGINE_RECONSTRUCTION.md` §3, `SSPC_NATIVE_ENGINE_MEASURE`) [E]:
`0x43d590` — 1392 вызова/кадр, **4859 мкс/кадр включительно, 2051 исключительно**; `0x43d480` — 5118/кадр,
2163 вкл., 1219 искл. Вложенные вызовы нельзя вычитать из родителя как независимую экономию.

Почему прямой перевод не ускоряет (R5, подтверждено): это тот же x86-64, исполняемый нативно; `cue_commit` native
дал −0,5 FPS в шуме. Выигрыш рендер-подготовки теней уже забран CITY-OPT Phase 5/6 (shadow runs на `0x43d480`:
поток 1 34,1→30,3 мс, FPS 27,9→31,6 в контрольной серии пресета) — он в пресете стенда.

Рассмотренные направления (каждое — отдельный флаг, по умолчанию выкл.; ни одно не реализовано без доказанной
эквивалентности):

| Направление | Потенциал | Решение |
|---|---|---|
| shadow instance batching | движок уже рисует одинаковые объекты одним draw с экземплярами (22 650 объектов → ~4 900 draw, R5-F §2); серии между каскадами — ~13 % теней, требуют выбора каскада в шейдере | REJECTED (нет эквивалентной экономии без смены семантики) |
| shadow material caching | `0x448640` вызывается только при смене материала; указатель таблицы ресурсов меняется на каждом коммите CUE (CITY §2) — кэш «по совпавшему указателю» не срабатывает (0 попаданий, CITY §5.1) | REJECTED |
| matrix optimization | матмул объект×VP на экземпляр (строки 358–434); входы уникальны на объект/каскад/кадр (R5-F §2, CITY Phase 5 §2) — дублей нет | REJECTED (нет повторных вычислений для кэша) |
| resource binding opt | привязки уже сокращены сериями CITY-OPT | вне владения R6-S |
| shadow draw opt | накладные на подготовку/передачу — забраны shadow runs | вне владения R6-S |
| cascaded shadows | повтор между каскадами ~13 % (R5-F §2) | REJECTED (смена семантики вывода) |

Вывод S2 [H+E]: в границах S3 (не отключать тени, не снижать качество, не ломать shadow runs) и при уже
действующих сериях CITY-OPT новой подтверждённой CPU-экономии в теневом цикле не найдено. Единственный честный
следующий шаг — полная OFFLINE_VERIFIED-реконструкция `0x43d590` (харнесс §2.1) как точка, где известен смысл
матриц и записей, для будущего нативного рендера (как §10 `NATIVE_ENGINE_RECONSTRUCTION.md`), а не ради FPS.
