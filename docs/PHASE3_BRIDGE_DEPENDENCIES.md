# Phase 3 — таблица BRIDGE-зависимостей (гостевые импорты)

Сгенерировано `tools\phase3_deps.py` из матриц `tools\migration_matrix.py` двух прогонов одной сборки (`logs\performance\p25_final_ab`, HEAD `2d1cafe`, патчи 0001–0020 — эталон Phase 3): «По умолч.» = прогон `PO1_1` (BRIDGE 275), «TM» = прогон `TM` (`--native threads --native memory --memory-commit on-demand`, BRIDGE 245). «История» — максимум вызовов из матрицы P2.2.3 (`docs\PHASE2_NATIVE_MIGRATION_MATRIX.csv`: прогон и длинные ручные сессии — граффити, бой). Прогон = 98 с: загрузка «Продолжить» → пляж Salmon Bay → поворот камеры в густую листву.

Это таблица **гостевых импортов** (метрика 1). Внутренние зависимости runtime от shadPS4 (слот TCB, патчер `fs:`, VEH, потоки моста, часы, старт библиотек моста) — метрика 2, `docs\PHASE3_INDEPENDENT_RUNTIME.md` §4. P3.3 (свой слот TCB и патчер `fs:`) импорты не меняет: это внутренние механизмы.

Классы: **A** — системные функции игры (libkernel, libc): runtime SecondSonPC должен владеть ими; **B** — графический мост (GnmDriver, VideoOut и очереди событий, в которые мост доставляет флипы и EOP) — Phase 4; **C** — сервисы подсистем (звук, видео, сохранения, NP, сеть, трофеи, диалоги), вызываются, остаются адаптированными до своей фазы; **D** — импортируются, ни разу не вызваны в записанных прогонах и сессиях.
