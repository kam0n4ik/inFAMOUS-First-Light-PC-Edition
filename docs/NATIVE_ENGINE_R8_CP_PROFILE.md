## 1. Профайлер

| Что | Где |
|---|---|
| код | `src/runtime/gpu/r8/cp_profile.{h,cpp}` (`cmake/r8/profile.cmake`) — коммиты `a8b2457`, `2360f11` |
| маркеры `[shared]` | `050d2a4`: только однострочные `R8_CP_PROF*` + include в `native_backend.cpp`, `command_processor.cpp`, `parallel_cp.cpp`, `vk_executor.cpp` (владельцы логики — A2/A3) |
| `shader/*` | не тронут; фронтенд меряется вокруг вызовов `PrepareDraw`/`PrepareDispatch`/`Invalidate`, разбивка внутри — существующий `SSPC_GPU_TIMINGS=sample:N` (`GS::FineSample`) |

Флаги (все выкл. по умолчанию; выключенный маркер = загрузка статического байта + ветка):
- `SSPC_R8_CP_PROFILE=1` — секции; `=2` — плюс перепись повторов (§5; дорогая, только для анализа);
- `SSPC_R8_CP_PROFILE_WINDOW=<от>:<до>` (с; по умолчанию 70:148 — окно стенда города);
- `SSPC_R8_CP_PROFILE_SAMPLE=N` (32) — каждый N-й пакет PM4 разбирается по классам opcode;
- `SSPC_R8_CP_PROFILE_CSV=1` — `logs\r8_cp_profile.csv`, строка на кадр (сводка: `E:\research\r8\profile\tools\csv_summary.py`).

Устройство [A]:
- **точные секции** (`R8_CP_PROF(sec)`): RAII на `__rdtsc()`, стек на поток, **собственное** время (вложенная секция
  вычитается из внешней) — секции потока в сумме дают его стену между кадрами; `Other` — непокрытое маркерами.
  thread_local `constinit` счётчики, без блокировок и общих записей на горячем пути;
- **кадр**: поток 1 сдаёт строку на маркере флипа (`R8_CP_PROF_FRAME` в `CommandProcessor`), поток 2 — перед своей
  следующей записью, увидев новый номер кадра; кольцо 8192 кадров на поток + итог прогона;
- **сэмплированные пакеты** (`R8_CP_PROF_PACKET/DECODED` в `CommandProcessor::Step`): у каждого N-го пакета внутри
  секции `Packets` — время `Next`/декода и собственное время исполнения по классу opcode (×N). Сэмпл несёт свои
  `rdtsc` и «лёгкие» маркеры (`BuildDraw`, запись `RegisterFile`, запись журнала регистров), поэтому сырые значения
  завышены (сумма ×1,38 к секции); столбец **share** нормирует классы на секцию `Packets`;
- **классы**: compute (своя работа), sync (поток 1 ждёт поток 2 в drain — по `DrainReason`), wait (очередь/журнал
  полны, чтение поверх записи GPU, `Synchronize`), idle (нечего делать, не входит в «busy»);
- отчёт — раздел `R8 CP profile` в `gpu_native.txt`: окно и весь прогон, мс/кадр, % busy, вызовы/кадр, нс/вызов,
  оценка стоимости маркеров (калибровка пары Enter/Leave на старте потока 1: 63–79 тиков).

Переиспользовано, не продублировано: разбивка фронтенда — `SSPC_GPU_TIMINGS=sample:32`; счётчики
`FrontendStats` (memo, SRT reads), `SrtDiag`, census, `DrainReason`, отчёт ParallelCp — в том же `gpu_native.txt`.

## 5. Повторная обработка уже известного (`p2_city_census`, окно, 2032 кадра) [E]

дескрипторы буферов/текстур/сэмплеров/вершин — по полям) сравнивается с прошлой подготовкой **той же программы**
(не только соседней), отдельно — 16 dword user data.

| подготовок/кадр | 4550 | 4550 |
| тот же результат, что у прошлой подготовки программы | **0,4 %** | **47,9 %** |
| те же регистры (user data) | 0,2 % | 26,5 % |
| тот же результат при других регистрах (новый снимок CUE с теми же байтами) | 0,2 % | 21,5 % |

Время фронтенда по классам draw (мс/кадр): PS повторён — **2173 draw, 4,54 мс** (shadow 1289/1,84, без тега 452/0,66,
mesh 291/1,18, G-buffer 141/0,86); ничего не повторено — 2358 draw, 7,64 мс; обе стадии / только VS — ≈ 0.
Повторённые draw **не дешевле** (mesh 4,05 мкс против 3,35, G-buffer 6,1 против 3,85): фронтенд делает всю работу
заново — памятка P4.7 почти не срабатывает (taken again 257 k за прогон), т.к. она хранит одну прошлую подготовку на
аппаратную стадию, а программы чередуются, и любое `GuestMemoryChanged` её сбрасывает.

Копии стадий: 9100/кадр (2,07 мс), неизменённых с прошлой копии (FB-6, `StageGeneration`) — 47/кадр: пропуск копий
по поколению потенциала не имеет.

Сверка с R7-R: версия привязки Native Resource State сохраняется у 41,7 % снимков PS и 0,13 % VS — совпадает с
переписью (PS 47,9 %, VS 0,4 %): **знание нативного движка полезно только PS-стадии**; VS (константы объекта на
каждый draw) надо делать дешевле, а не пропускать. Повтор декода тех же регистров: 66 % записей регистров не меняют
значение (`register writes 1067 M, changing a value 34,1 %`).

## 7. Ограничения

- Одиночные прогоны; разброс города между прогонами ±0,5 FPS. Накладные расходы `=1` — серия на этапе 2.
- Сэмплированные классы пакетов нормированы на секцию в предположении одинакового завышения сэмпла.
- Перепись `=2` сравнивает результат стадии без `SpecializationKey`/runtime (модуль их покрывает) и без
  user data `flat[0..16)` (их отдельно учитывает «те же регистры»).
- Время внутри фронтенда — только средние `SSPC_GPU_TIMINGS=sample:32` (VS/PS раздельно не видны без `shader/*`).
