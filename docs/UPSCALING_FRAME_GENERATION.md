# Масштабирование (DLSS / FSR 3.1) и генерация кадров (FSR 3.1 FG)

Ветка `feature/upscaling-framegen` (worktree `E:\SecondSonPC-upscale`), только собственный бэкенд `--gpu-backend sspc`.
Коммиты: `c72630e` апскейл, `66e9b4d` меню F1, `16ee136` FSR Frame Generation.

## Как это встроено в кадр игры (всё измерено, не предположено)

| Что | Где | Как найдено |
|---|---|---|
| Внутреннее разрешение | движок хранит размер дисплея (+0/+4) и рендера (+0xC/+0x10) в `0x1eff00`; патч непосредственных значений в `0x1eff47` до старта | путь PS4 Pro: сцена меньше буфера дисплея, игра сама масштабирует её в проходе `post`, UI рисуется поверх в 1920×1080 (HUD при 720p так же чёткий, как в нативе) |
| Векторы движения | проход 29 (`CFxVelocityBuffer`), RG16F размера рендера; полное движение (камера+объекты), текущая − предыдущая позиция в UV, y вниз | перепроекция прошлого кадра: ошибка 3,1–3,5 против 16–22 без векторов / с другим знаком; масштаб для апскейлера (−W, −H) |
| Глубина | `0x26b200000` D32F, **обратная** (небо 0) | дамп; копируется в конце прохода 29, т.к. UI-проход 34 её перезаписывает |
| Цвет | сцена после тонмаппинга (RGBA8 размера рендера), которую сэмплирует первый draw в буфер дисплея | трасса кадра P5.3A при 720p |
| Jitter | Halton(2,3) смещением вьюпорта только для геометрии сцены (draw со сценовой глубиной до прохода 29, не полноэкранные), LOD bias текстур log2(рендер/вывод) | знак (+,+): лучший PSNR к нативу, остальные три варианта дают сетчатую рябь |
| Свой TAA игры | **SMAA T2x**: `0x472810` каждый кадр сдвигает окно фрустума камеры (`*(0x7f2d2b8)+0x5ac`) на ±0,5/ширину при флаге `0xda07f9`, проход 32 смешивает два кадра | константы проекции чередуются ±0,25 px; на время апскейла проба сбрасывает флаг и окно — иначе jitter гасился в 4 раза и вход DLSS был смазан |

Апскейлер заменяет игровое масштабирование: выход (1920×1080) подставляется вместо текстуры сцены в draw прохода `post`, после чего игра сама рисует интерфейс — HUD не проходит через апскейлер.

DLSS в Vulkan требует `VK_NVX_binary_import`, а он поднимает CUDA-часть драйвера, которой нужно ~48 ГиБ адресов ниже 1 ТиБ; гостевая память занимает их все → `vkCreateDevice` = −3 (доказано отдельной программой). Решение: `cuInit` до резервирования гостевой памяти с временным захватом всего ниже `0xF000000000` (CUDA встаёт в окно 0xF1…0xFD00000000, игра туда не обращается).

## Качество картинки (пляж, неподвижная камера, кадр 2400; дисперсия лапласиана = резкость)

| Режим | Резкость |
|---|---|
| нативный 1080p | 286 |
| игровой апскейл 720p→1080p | 45 |
| DLSS Quality + RCAS 50 % | 253 |
| FSR 3.1 Quality (RCAS 50 %) | 213 |

## Производительность (RTX 2060, 1 прогон 90 с на режим, статистика 62–88 с)

| Режим | Деревня FPS / 1% low / GPU мс | Пляж FPS / 1% low / GPU мс | Апскейлер GPU мс | VRAM МиБ |
|---|---|---|---|---|
| Нативный | 35,4 / 25,8 / 21,3 | 41,6 / 28,0 / 14,2 | — | 1551 |
| DLSS Quality | 36,3 / 27,8 / 18,4 | 38,8 / 26,8 / 13,2 | 2,6 | 1607 |
| DLSS Performance | 35,4 / 29,2 / 19,5 | 39,0 / 26,8 / 13,7 | 4,2 | 1604 |
| FSR Quality | 38,7 / 29,2 / 18,8 | 44,7 / 29,3 / 12,0 | 1,3 | 1533 |
| FSR Performance | 40,7 / 29,2 / 16,5 | 45,3 / 29,3 / 10,6 | 1,1 | 1489 |

Кадр ограничен командным процессором на CPU (~20–23 мс), поэтому снижение разрешения ускоряет только GPU-часть. На RTX 2060 DLSS дорогой, его выигрыш почти съедается; FSR даёт +9…15 % в деревне. Серия — по одному прогону, разброс прогонов ±1–2 FPS.

## Генерация кадров

| Режим | Игра, кадров/с | На экране, кадров/с |
|---|---|---|
| Пляж, FSR Quality + FSR FG | 43–53 | 86–105 |
| Деревня, DLSS Quality + FSR FG | 34,5–35,7 | 69–71 |
| Деревня, FSR Native AA + FSR FG | 29,7–32,7 | 59–65 |

Настоящие кадры игры и реально показанные swapchain FidelityFX (`GetLastPresentCount`) считаются отдельно, строка лога `[FSR-FG]` раз в 5 с. Симуляция и тайминги игры не меняются (FPS игры с FG 43,2 против 44,7 без него). Генерация выключается в кадрах без входов сцены (меню, ролики, загрузки, сброс истории). HUD отделён: FidelityFX получает кадр без интерфейса (буфер дисплея после сцены, до первого draw UI).

**Не проверено:** сгенерированные кадры глазами (дым, вода, листва, быстрые повороты, HUD) — нужен ручной просмотр; задержка ввода не измерялась; Vulkan Validation с FG не прогонялась.

## Не сделано / блокеры

- **DLSS Frame Generation / Multi Frame Generation / Reflex:** не реализованы. RTX 2060 их не поддерживает (DLSS-G — RTX 40/50), проверить интеграцию через Streamline на этом железе невозможно; в меню строки заблокированы с причиной. SDK Streamline 2.14.1 скачан, заголовки и DLL подключены к сборке.
- **Выходное разрешение выше 1920×1080:** апскейлер пишет в буфер дисплея игры; больше — смена размера дисплея и раскладки UI игры.
- **Смена технологии/качества/генерации** — после перезапуска (размер рендера и swapchain задаются при старте); резкость — сразу.

## Включение

F1 → «Масштабирование и генерация кадров», или `settings.toml` `[Graphics]`: `upscaler = "dlss"|"fsr"|"off"`, `upscaleQuality = "native"|"quality"|"balanced"|"performance"|"ultra"`, `upscaleSharpness = 0..100`, `frameGeneration = "off"|"fsr"`. Автопрогоны: `SSPC_UPSCALER`, `SSPC_UPSCALE_QUALITY`, `SSPC_UPSCALE_SHARPNESS`, `SSPC_FRAME_GEN`. Рядом с exe: `sspc_dlss.dll`, `nvngx_dlss.dll` (DLSS), `amd_fidelityfx_vk.dll` (FSR, FSR FG).

Лицензии: мост NGX (`src/dlss_bridge`) — MIT, адаптирован из shadPS4-Bloodborne-DLSS-FSR (IFreemz); `nvngx_dlss.dll` — по лицензии NVIDIA DLSS SDK (распространение DLL разрешено); `amd_fidelityfx_vk.dll` (подписанная сборка FidelityFX SDK 1.1.4) и Streamline — MIT. Бинарники SDK в репозиторий не кладутся (`third_party/upscalers`, gitignored).
