# CITY-OPT: FPS в городе на собственном Vulkan-бэкенде

Цель — приблизиться к стабильным 60 FPS в городе без генерации кадров. Это цель, а не обещание: ниже только
измеренные цифры. Все оптимизации включаются флагом `SSPC_CITY_PERFORMANCE=1` (пресет в `cp_mode.cpp`). Каждая из них
— своя переменная окружения: явно заданное значение, в том числе `=0`, пресет не трогает. Без флага обычный режим
остаётся прежним.

Стенд: RTX 2060 6 ГБ, Ryzen 5 5500, 32 ГБ. Сцена — город (`run_phase0.ps1`, 150 с, сохранение `logs\hl\p0`, клавиши
`space@12,space@22,w@60:3`), режим CP native, прогретый кэш шейдеров. Окно замера — 70–148 с прогона (`gpu_frames.csv`).

## Что ограничивает FPS в городе

| | Город | Пляж |
|---|---|---|
| draw / кадр | ~12 000–12 600 | ~5 500 |
| поток 1 (CP + фронтенд шейдеров), работа | ~32 мс | |
| поток 2 (запись Vulkan) | ~32–36 мс | |
| GPU | ~17,7 мс | |

- GPU занят меньше половины кадра. Узкое место — два CPU-потока GPU-бэкенда, оба по ~2,5–2,8 мкс на draw.
  Главный поток игры ~88 % времени ждёт их в цикле ожидания (`eboot+0x53b2b0`, docs/PHASE2_P25_PERFORMANCE.md).
- Собственный переводчик шейдеров не причина: с мостом shadPS4 город даёт те же 21–26 FPS.
- Пока цена draw прежняя, потолок около 30 FPS: при 12 000 draw кадр в 16,7 мс требует ≤1,4 мкс на draw в каждом
  потоке.
- Откуда берутся draw (кадр 3021, 12 210 draw): тени (цель глубины `2ff4d0000`, без цветовых целей) — 4 843;
  освещение/прозрачность в `2fcdf0000` — 3 292; G-buffer (5 целей) — 1 979; остальное — мелкие проходы. По конвейерам
  лидируют p87 (4 386, тени) и p462 (2 713, мелкие меши одного шейдера).

Профиль xperf (поток 2): `RecordDraw` 74 %, из них `BindStage` 30 % (`GuestRange` 16,5 %), драйвер `nvoglv64` ~20 %,
`PushDescriptors` 8,5 %, `SetDynamicState` 7,7 %. Поток 1: `ShaderFrontend::PrepareStage` 38,5 %
(`ResolveResources` 21,6 %), `CopyStage` 9,1 %, `RegisterFile::Write` 7,6 %.

## Phase 1

### SSPC_CITY_DYN_MEMO=1 — динамическое состояние не пересчитывается

`Executor::SetDynamicState` на каждом draw собирал viewport, scissor, depth/stencil, bias, cull, blend constants и
маски записи цвета из регистров, сравнивал их с тенью `dyn_` и записывал отличия. Теперь он запоминает свои входы
(`DynMemo` в `vk_executor.h`):

- версии групп регистров, из которых читает (`Cp::RegisterFile::Version`). Версия группы растёт при любом реальном
  изменении значения в ней: Write, Reset, Load, ClearContext. Это ключ по содержимому, а не по адресам. При первом
  вызове собираются группы всех читаемых регистров (11 групп); регистр вне групп выключает кэш;
- поля состояния конвейера, которые он читает (`prim_type`, `mrt_mask`, маски записи целей), индексированность draw;
- джиттер апскейлера.

Если входы те же и `dyn_` действителен (тот же command buffer: `Begin` и апскейлер сбрасывают `dyn_.valid`), ни одна
команда не нужна — всё уже установлено. Кэш срабатывает на ~90 % draw (3,9 млн попаданий за прогон с валидацией).
Счётчик — строка «dynamic state not computed again» в `gpu_native.txt`.

`SSPC_CITY_DYN_MEMO=ab:<n>` — для сравнения изображений: кэш включён только в нечётных блоках по n кадров.

### SSPC_CITY_HOT_LOCKS=1 — без двух мьютексов на draw

- `VideoOut::NextFlipId()` поток записи спрашивает для каждого диапазона буфера каждого draw. Раньше — под мьютексом
  порта, теперь — атомарная копия `g_next_flip_id`, которая пишется вместе с `next_flip_id` под тем же мьютексом.
- `Executor::UpscaleOnTargets` на каждом draw брал настройки апскейлера под мьютексом. Теперь при выключенном
  апскейлере выходит сразу по атомарному `Upscale::BackendOn()`.

### Проверки Phase 1

- Изображение (`logs/cityopt_img2`, захваты удалены после анализа). Игра на паузе-карте, кадры 3600+64,
  `SSPC_CITY_DYN_MEMO=ab:4`: кэш включается поблочно в одном прогоне. Каждый кадр «вкл» сравнивался с ближайшим
  «выкл», а «выкл» с «выкл» дают уровень шума застывшей сцены:
  - итоговый кадр `26c568000`: «вкл» 19/32 бит в бит, шум 20/32;
  - G-buffer `2f9e10000`: 8/32 против 8/32;
  - освещение `2fcdf0000`: 8/32 против 8/32, худший кадр «вкл» 233 556 байт против 224 243 у шума;
  - атлас теней `2ff4d0000`: 32/32 бит в бит у обоих.

  Различий сверх шума нет.
- Vulkan Validation + Synchronization Validation (`--gpu-native-validate`), город, `SSPC_CITY_PERFORMANCE=1`, 170 с
  (`logs/runs/val_city1`): **0 сообщений**, `[Error]` 0, device lost 0.
- Поколение кэша шейдеров не изменилось (`aeb2a6e78ccfe5a8`): `src/runtime/gpu/shader/*` не тронут.

### Отклонено в Phase 1

- `SSPC_P53_FRONTEND_THREAD=1` (фронтенд на третьем потоке): на текущих настройках — 0xC0000005 на 24-й секунде.
  Не включается.
- Фильтр инвалидаций кэша программ по страницам: правка в `shader/shader_cache.*` меняет поколение кэша шейдеров
  (полная подготовка шейдеров при следующем запуске). Откачено до замера.

## Phase 2–3: draw, отличающиеся только геометрией

Разбор движка — `docs/CITY_ENGINE_REVERSE.md`. p462 — проход 14 (`0x1a1960`, ~2 800 draw за кадр): статические меши,
у соседних draw отличается только таблица V# (user data VS `s2`) и индексы. Геометрия уже в видеопамяти
(`BufferCache`, 0 копий CPU → GPU); дорога обработка каждого draw в обоих потоках.

### Флаги (входят в `SSPC_CITY_PERFORMANCE=1`, каждый отключается своим `=0`)

- `SSPC_CITY_GEOFAST=1` (поток 1, `ParallelCp::PrepareGeometryOnly`): draw сразу за подготовленным draw, если между
  ними изменились только группы VS user data / индексов / параметров draw, user data VS — только в парах fetch-таблицы,
  шейдеры и user data PS те же, поколение памяти фронтенда то же, у предыдущего нет записей и копий SRT: подготовка
  предыдущего + свои вершинные привязки (V# перечитаны, как в `DecodeResources`). `=verify`: полная подготовка тоже и
  сравнение по полям — **13 353 987 draw, 0 расхождений**.
- `SSPC_CITY_BATCH=1` (поток 2, `Executor::Batchable` / `DrawPreparedBatch`): подряд опубликованные draw с тем же
  состоянием, ресурсами, константами и целями, отличающиеся только геометрией, — один `vkCmdDrawIndexed`: вершины
  подряд, индексы 32-битные со сдвигом, порядок примитивов прежний. Только списки треугольников VS+PS, без
  перезапуска примитивов, без записей в память, без запросов окклюзии; шейдер не читает номер вершины / базовую
  вершину (VS) и номер примитива (PS) — либо читает в переменную, перезаписанную до чтения (проверка SPIR-V без
  ветвлений). Не склеилось — каждый draw отдельно с его регистрами. `=ab:<n>` — блоками для сравнения изображений.
- `SSPC_CITY_GEOMETRY_CACHE=1`: геометрия серии хранится в видеопамяти (2 арены × 64 МиБ, BAR,
  `SSPC_CITY_GEOMETRY_CACHE_MB`), ключ — точный состав серии, действительна, пока версии 64-КиБ блоков источников в
  `BufferCache` те же (растут при любой инвалидации и записи GPU; источник обязан быть резидентным, т. е. защищённым
  от записи). Арены перерабатываются по очереди только после завершения GPU.

| C: + склейка | 24,4 | 17,0 | 33,1 | 32,8 | 38,3 | 7,4 МБ |

Прогоны F (27,6–27,9) выше прогонов A (25,4–26,6). Поодиночке выигрыша нет: предел уходит во второй поток. Склейка
объединяет ~3 100 draw за кадр в ~140 серий: **Vulkan draw ~9 200 вместо ~12 250 (−25 %)**. Кэш геометрии без
склейки не используется (геометрия p462 и так в видеопамяти), поэтому «только кэш» = A.

Проверки: Vulkan Validation + Sync, город, все флаги (`logs/runs/val_p3`) — **0 сообщений**, `[Error]` 0. Изображение
(`SSPC_CITY_BATCH=ab:4`, пауза, кадры 3600+64): глубина `26b200000` и тени `2ff4d0000` — 32/32 бит в бит; итоговый кадр,
G-буфер, освещение (цель прохода 14) — в пределах шума соседних кадров без склейки. Фоновая нагрузка во время замеров:
процесс браузера ~110 % CPU — абсолютные FPS ниже дневных.

### Отклонено

- `SSPC_P53_FRONTEND_THREAD=1`: гонка исправлена (`87da20e`), но поток 2 с ним на 20–30 % медленнее на команду — 21–24
  FPS. Привязка потоков к ядрам и ограничение глубины очереди — хуже (удалены).
- Ожидание на краю опубликованных записей ради стабильных границ серий — без выигрыша (удалено).
- Тени (`0x43d480`, ~4 800 draw, константный буфер 0x48 байт на draw) и G-буфер (`0x1a1770`, 0xd4 байт) не склеиваются
  без instancing на уровне шейдера.

### Ограничения

60 FPS в городе не достигнуты: оба потока ~30 мс. Дальше — instancing теней/G-буфера (изменение трансляции шейдеров) и
снижение цены разбора PM4 и `CopyStage` в потоке 1.

## Phase 4: шаблоны draw и склейка теней (подробно — `docs/CITY_DRAW_PRECOMPUTE.md`)

Флаги, **не входящие** в пресет (каждый отдельно, выключены по умолчанию):

- `SSPC_CITY_DRAW_CACHE=1` (с GEOFAST): подготовка предыдущего draw — шаблон и для draw с другими константами/текстурами
  у стадий без обхода SRT (план заново из user data, тот же ключ специализации). verify — 22 млн draw, 0 расхождений.
- `SSPC_CITY_INSTANCING=1|ab:<n>`: серии, отличающиеся и константным буфером VS (тени), — `vkCmdDrawMultiIndexedEXT`;
  SPIR-V VS правится в исполнителе (`DrawIndex * шаг` к смещению буфера), геометрия — прямо из видеопамяти кэша
  буферов. Validation + Sync 0, тени и глубина бит в бит.
- Диагностика `SSPC_DIAG_PREP_CENSUS=<кадр>:<кадров>`: цена draw в обоих потоках по паре шейдеров, причины отказов
  GEOFAST и концов серий склейки; `SSPC_DIAG_INSTANCING_DUMP=1` — правленые модули в `logs\p44`.

Итог: работа потока 1 −0,4…−1,3 мс, запись потока 2 −0,6…−2,1 мс, команд draw Vulkan −15 %; FPS в пределах шума
(B 25,0–26,6 / E 25,9–26,8 при разбросе прогонов ±2,5 FPS). В пресет не включены.
