# Phase 4 · P4.4 — собственный Vulkan-бэкенд (`--gpu-backend sspc`)

Статус на 2026-10-11 ~07:30: **P4.4 IN PROGRESS** (не COMPLETED: см. §10). Игра на эталонном маршруте рисуется
собственным Vulkan-бэкендом SecondSonPC (мост shadPS4 — только транслятор шейдеров P4.3), картинка совпадает с мостом
с включёнными readbacks, валидация и синхро-валидация полного маршрута — 0 сообщений, ~16,5 FPS (было 6–8). Мост по
умолчанию не изменён. Локальные коммиты `c3b0a9e`…`fe52916`, без push.

Доказательная база (все таблицы, прогоны, опровергнутые гипотезы): `logs\p44\diag\EVIDENCE.md` (циклы 1–4).

## 1. Как запускать

```
SecondSonPC.exe --loader sspc --gpu-backend sspc [--gpu-native-validate] [--gpu-native-diag]
```
- `--gpu-backend sspc` включает собственные GnmDriver/VideoOut и бэкенд; без флага — проверенный путь моста.
- `--gpu-native-validate`: VK_LAYER_KHRONOS_validation + synchronization validation → `logs\vk_validation.log` (VUID,
  объекты, номер отправки). Слой — Vulkan SDK 1.4.363 в `E:\VulkanSDK`. Под валидацией sparse-binds ждёт хост (§5).
- `--gpu-native-diag`: журнал команд, NV checkpoints, buffer markers, имена объектов, `logs\gpu_alias.log`.
- Воспроизводимый маршрут: `powershell -File logs\p44\diag\run_route.ps1 -Tag <имя> [-Seconds 90] [-Backend sspc|bridge]
  [-Validate] [-Diag] [-Short] [-Env "A=b;C=d"]` — каждый раз свежая копия снимка `logs\performance\p43_ab\snapshot` в
  `logs\p44\profile_cmp` (снимок не меняется), маршрут P4.3, артефакты в `logs\p44\diag\<имя>`.
- Отчёт бэкенда при выходе: `logs\gpu_native.txt` (STATUS, счётчики, кэши, ожидания, метки, VideoOut, барьеры).
- DEVICE_LOST: отправки прекращаются, один отчёт `logs\gpu_device_lost.txt`, процесс завершается с кодом 5.

## 2. Архитектура

| Компонент | Файлы | Роль |
|---|---|---|
| Gnm/VideoOut | `gpu\gnm\*`, `gpu\native_videoout.*` | функции игры; flip-очередь, метки буферов дисплея, vblank 59,94 Гц |
| Командный процессор | `gpu\command_processor.*` (P4.2, режим Isolated) | PM4 очередей; метки/fence держатся до завершения работы на GPU |
| Исполнитель | `gpu\vulkan\vk_executor.*` | draw/dispatch/flip/DMA → command buffers (batch по 500 draw), timeline |
| Кэш образов | `gpu\vulkan\vk_image_cache.*` | образы/виды/семплеры, детайлинг, правила перекрытия моста, переходы layout |
| Буферный кэш | `gpu\vulkan\vk_buffer_cache.*` | sparse-зеркало адресов GPU (512 ГиБ, блоки 64 КиБ), write-back, трекинг |
| Гостевые буферы | `gpu\vulkan\vk_resources.*` | импорт памяти гостя через backing view (`VK_EXT_external_memory_host`) |
| Трекер страниц | `gpu\page_tracker.*` | защита записи гостевого view, обработчик ошибок, блоки 64 КиБ |
| Презентер | `gpu\vulkan\vk_presenter.*` | swapchain (MAILBOX), копия кадра в свой образ при записи flip |
| Диагностика | `gpu\vulkan\vk_diagnostics.*`, `gpu\cpu_sampler.*` | валидация, checkpoints, профили |

Ключевые решения (каждое — по замерам, `EVIDENCE.md`):
- **Буферы**: чтение шейдером — из sparse-зеркала в видеопамяти (страницы загружаются из host-импорта, затем
  защищаются от записи; запись CPU инвалидирует). Мелкие (≤16 КиБ) диапазоны только для чтения — копия CPU в кольцо
  (как STREAM_THRESHOLD моста). Записи GPU копируются обратно в память гостя в конце batch (write-back).
- **Записи dispatch** (≥8 рабочих групп, привязка ≤256 КиБ) идут в плотные «тени» (device-local кольцо 128 МиБ):
  запись шейдера в sparse-память на RTX 2060 / 596.21 медленнее плотной в ~150 раз (скиннинг 834 → 5,5 мкс).
- **DMA M2M** и WRITE_DATA в гостевую память — на шкале GPU (`vkCmdCopyBuffer`/`vkCmdUpdateBuffer`), без ожидания CPU.
- **Метки EOP/RELEASE_MEM** пишутся после фактического завершения работы на GPU (P4.2 CompleteWork) — не раньше.
- **Кэши горячего пути**: цели рендеринга (по версиям групп регистров), дескрипторы текстур (по T#), динамическое
  состояние (тень на command buffer), плоская таблица блоков буферного кэша.

## 3. Корректность

| Проверка | Результат | Прогон |
|---|---|---|
| Валидация + синхро-валидация, полный маршрут 90 с | 0 сообщений | `d7`, `e7`, `f4`, `g7`, `k1` |
| DEVICE_LOST | 0 во всех прогонах после исправлений цикла 1 | все |
| Картинка (90 с маршрута) | скалы с текстурами, Делсин, растительность, длинный дом, освещение | `k2_texmemo_perf\screen.png` |
| Сравнение с мостом по умолчанию | мост темнее (сумерки) | `h1_bridge_ref` |
| Сравнение с мостом, readbacks precise | совпадает с собственным (дневная сцена) | `h2_bridge_readbacks` |

**Метод сравнения**: один маршрут `run_route.ps1` (одинаковые нажатия по времени), снимок окна на 90 с. Допуск —
визуальный: одинаковая сцена, геометрия, текстуры, освещение и экспозиция; кадр в кадр не совпадает (разный FPS →
разные фазы анимации, ветра, частиц). Тёмная «сумеречная» картинка моста по умолчанию — артефакт выключенных readbacks
shadPS4 (CPU игры не видит результатов GPU, экспозиция застревает); собственный бэкенд возвращает все записи GPU
(write-back), его экспозиция совпадает с мостом с readbacks.

Найдены и исправлены (с доказательством): недопустимые виды глубины/трафарета и layout дескрипторов (VUID 01761, 01976,
00344, 09600, 09592, 01197), формат вершинных атрибутов (08734 → тёмные материалы), гонка `PageTracker::OnFault`
(падение 0xC0000005), порча соседних выходов скиннинга через выровненный префикс дескриптора (WRITE_AFTER_WRITE),
унаследованное динамическое состояние (07834/07629).

## 4. Производительность

Маршрут 90 с, 1280×720 окно (внутренний 1080p игры), RTX 2060, без диагностики:

| Шаг | FPS | Командный процессор, мс/кадр | GPU, мс/кадр |
|---|---|---|---|
| первый рабочий кадр (до буферного кэша) | 6–8 | — | 125 |
| буферный кэш | 7,8 | 82,8 | 47,6 |
| тени записей dispatch | 11,6 | 67,8 | 34,4 |
| кэш целей, batch 500, плоская таблица | 13,1 | 61,5 | 30,7 |
| инвалидации по адресу, переиспользуемые списки | 15,8 | 48,2 | 30,0 |
| тень динамического состояния | 16,7 | 44,5 | 30,0 |
| кэш текстур, тени от 8 групп | 16,5 | 43,7 | 27,2 |

Для сравнения на том же маршруте: мост по умолчанию 43 FPS (без readbacks, неверная экспозиция), мост с readbacks
precise — 21 FPS.

**Что ограничивает кадр** (l1–l8): главный поток игры ~96% времени крутится в ожидании, пока счётчик EOP графической
очереди (`0x248000000`) достигнет только что отправленного кадра — у игры в полёте один кадр. Время кадра ≈ задержка
обработки кадра командным процессором (~44 мс: запись команд ~35, разбор PM4 ~9) + хвост GPU + ответ игры (~15 мс).
Мост быстрее, потому что пишет EOP при разборе пакета (раньше завершения GPU) — ценой неверных данных для CPU.
Рычаг дальше — CPU задержка командного процессора (разбивка: `logs\p44\diag\i1_sample\gpu_cpu_profile.txt`).
60 FPS не достигнуто и не заявляется.

## 5. Синхронизация и известные свойства инструментов

- syncval (VVL 1.4.363) не отслеживает сигналы семафоров `vkQueueBindSparse`: batch, ждущий bind-семафор, остаётся
  неразрешённым и все последующие present ложно помечаются WRITE_AFTER_PRESENT (A/B c5/c6/c7). Поэтому под
  `--gpu-native-validate` binds ждёт хост; без валидации очередь ждёт bind-семафор (обе схемы корректны).
- `__try/__except` в clang-cl без `-fasync-exceptions` не ловит ошибку встроенной загрузки — диагностика читает чужую
  память через `ReadProcessMemory`.
- Мелкие таймеры (`rdtsc`) в горячем пути по замеру не стоят времени (i2), профиль переоценивает их.

## 6. Память, VRAM, commit

Замеры на маршруте (`k2_texmemo_perf`, конец 90 с): видеопамять 1247 МиБ из бюджета 5186 МиБ; процесс private 2389 МиБ
(пик 2548), система 23,8 / 32,7 ГиБ commit (pagefile нет). Кэш образов: 2456 образов, 833 МиБ; буферный кэш: 123 МиБ
резидентно (бюджет 2560 МиБ, сверх бюджета — host-импорт), кольцо потоков 160 МиБ (host-cached), кольцо теней 128 МиБ.
Write-back ~48 МиБ на кадр. Образцы VRAM/commit пишутся каждые 5 с (`--vram-log 5`).
**Не сделано**: вытеснение образов (кэш образов только растёт; за 90 с без проблем, на долгой игре — риск) — §10.

## 8. Патчи моста

- `0032-native-gpu-no-imgui-context.patch`: `ImGui::Core::ProcessEvent`/`OnResize` выходят без контекста (окно моста без
  его презентера при `--gpu-backend sspc`).
- `0033-native-gpu-backing-run.patch`: `GpuMemory::BackingRun` — участок backing-памяти под гостевым адресом (импорт
  в Vulkan через backing view, а не через защищаемый гостевой view).

## 9. Известные пробелы (по маршруту не проявились)

1. Нет вытеснения образов; нет освобождения устаревших образов при повторном использовании адреса — записанный GPU образ
   не перезагружается, если CPU позже записал по его адресу текстуру того же формата (на маршруте 2 случая другого
   формата — загружены отдельно, верно).
2. Нет копирования меньшего образа в больший (ExpandImage моста) и BC поверх несжатого — такие текстуры загружаются из
   памяти (на маршруте только при загрузке уровня).
3. Запись шейдеров в sparse-зеркало медленная (тени — обход для dispatch; draw с UAV пишут в зеркало напрямую).
4. Командный процессор однопоточный; ~5600 draw/кадр по ~6 мкс CPU.
5. Тайлинг/форматы, не встреченные на маршруте, проверены только самотестами P4.1–P4.3.
