# CITY-OPT Phase 6: ресурсы draw G-буфера — от объекта движка до командного процессора

Phase 5 (`docs/CITY_ENGINE_OPTIMIZATION.md`) свела в серии draw мешей `0x1a1960` и теней `0x43d480`. После неё поток 1
(командный процессор + фронтенд шейдеров) — ~29–31 мс на кадр в городе; его самая дорогая часть — полная подготовка draw
G-буфера `0x1a1770` с обходом SRT. Эта фаза разбирает, как движок готовит ресурсы этих draw, и проверяет три способа
сократить их подготовку. Метки: **[A]** — анализ кода (Ghidra/REA), **[E]** — измерено, **[H]** — гипотеза.

Итог коротко [E]:

- Цепочка разобрана полностью [A]. Ключевой факт: CUE копирует таблицу ресурсов в новую память на каждом коммите
  (§2).
- **Серии G-буфера с зондом смены материала** (`SSPC_CITY_ENGINE_GBUFFER_RUNS=1`) вошли в пресет
  `SSPC_CITY_PERFORMANCE=1`, выключаются явным `=0`. Город, контрольная серия пресета (3 раунда, лучше в каждом):
  поток 1 **34,1 → 30,3 мс**, FPS **27,9 → 31,6**, 1 % low 24,2 → 26,6. verify — 0 расхождений. Изображение в
  пределах шума, глубина и тени совпадают бит в бит. Validation + Sync — 0 сообщений по записи команд. Пляж не хуже,
  деревня без изменений.
- Шаблон подготовки для стадий с обходом SRT (`SSPC_CITY_ENGINE_RESOURCES=1`) корректен, но выигрыша не даёт —
  отклонён, оставлен под флагом (§5.2).
- Цель «поток 1 — 25–27 мс» не достигнута: 30,3 мс в контрольной серии.

## 2. Цепочка: объект → материал → таблицы ресурсов → user data → CUE → PM4 → CP [A]

| Звено | Где | Что делает |
|---|---|---|
| Объекты прохода | `0x1a2030` (метод прохода мешей) | сортированный список объектов; вариант с экземплярами группирует подряд идущие объекты с тем же мешом и материалом |
| Записи экземпляров | `0x1a2030` → `0x1f0870` | на экземпляр — запись **0xD4 байт** (матрицы объекта, вида, параметры) в кадровом аллокаторе |
| Материал | `0x448640(pass, R, material)` | вызывается **только при смене материала** (`if (material != last) …`); дескрипторы материала читаются из постоянной памяти `*(material + 0x28)` |
| Draw | `0x1a1770(pass, R, records, n, mesh)` | см. ниже; при флаге `pass+0x124` вызывается дважды подряд с тем же материалом (второй раз — другой stencil) |
| Stencil | `0x1a1770` → `0x6229a0` | `SET_CONTEXT_REG 0x10C` (DB_STENCILREFMASK) — своё значение на класс меша |
| Константы кадра | `0x1a1770` → `0x120280` | |
| V# экземпляров | `0x1a1770` → `0x61e260` | буфер записей: шаг 0xD4, n записей |
| Слот VS | `0x16b70(cue, stage 2, slot pass+0x127, …)` | V# экземпляров — в слот VS-таблицы |
| Вершины | `0x16aa0` | таблица вершин VS |
| Экземпляры, коммит, draw | `NUM_INSTANCES`, `0x14ad0`, `drawIndex 0x623c60` | |

**CUE** (constant update engine движка) [A]:

- Функции слотов `0x16b70`, `0x169d0`, `0x16eb0`, `0x16d10` пишут по таблице отображения `cue + 0xc180 + stage*8`
  (на API-слот одно u16). Старший бит означает прямой `SET_SH_REG` (`0x626520`). Иначе значение уходит в теневую таблицу
  стадии `cue + 0x90 + stage*0x1800`. Любая запись ставит флаг `cue + 0xc1d0 + stage`.
- Стадии CUE: 0 — CS, 1 — PS (`0x2C0C`), 2 — VS (`0x2C4C`); таблицы `0x987c80` и `0xaf0070`.
- **Коммит `0x14ad0`**: для каждой «грязной» стадии выделяет блок в кольце кадра (`0x123d0`) и копирует туда теневую
  таблицу целиком (`memcpy`). Затем пишет в user data **указатель на новую копию** (`0x626400`).

Следствие: **указатель таблицы ресурсов в user data меняется на каждом draw**, даже когда содержимое таблицы то же самое.
Для CP такой draw — «другие user data». Обход SRT шейдера читает таблицу по этому указателю, поэтому повторное
использование результата обхода «по совпавшим регистрам» не срабатывает никогда (§5.1).

Что меняется от draw к draw внутри одного материала [A + E]: VS — слот V# экземпляров (`0x61e260`), таблица вершин,
указатель на копию таблицы. PS — указатель на копию таблицы, а при смене материала (`0x448640`) — дескрипторы. Stencil —
по классу меша.

## 3. Реализация (всё выключено по умолчанию)

### 3.1 Зонды движка (`src/engine/render/draw_runs.*`)

- `0x1a1770` — третий сайт зондов Phase 5 (`{0x1a1770, 0x1e4, 0x5bf111e570dcaaed}`). Метка `Source::GBuffer = 3` в
  теле NOP после draw. Ставится только при `SSPC_CITY_ENGINE_GBUFFER_RUNS` или `SSPC_DIAG_ENGINE_SRT`; без них Phase 5
  работает как раньше.
- `0x448640` — зонд смены материала (`{0x448640, 0x15f, 0x22c6fc74651c7374}`, пролог 17 байт, проверен в Ghidra).
  Запоминает контекст R в `thread_local`. Следующий `0x1a1770` того же R ставит в метку бит `kMaterialChanged` (0x100).
  Это только подсказка: CP по ней лишь **отказывает** draw в членстве серии и никогда по ней не принимает.

### 3.2 `SSPC_CITY_ENGINE_RESOURCES=1|verify` — шаблон подготовки для стадий с обходом SRT (`parallel_cp.cpp`)

Расширяет шаблон `SSPC_CITY_GEOFAST`: draw, который отличается от предыдущего только регистрами, получает подготовку
предыдущего draw. Если обход SRT читал изменившийся регистр, обход повторяется с новыми регистрами — та же программа
обхода, та же память и то же декодирование, что в полной подготовке, но без поиска программы, раскладки, fetch-шейдера
и модуля. Результат принимается, только если ключ специализации равен ключу модуля, а конец привязок совпал. Иначе draw
готовится полностью. verify: каждый такой draw готовится и полностью, затем результаты сравниваются.

### 3.3 `SSPC_CITY_ENGINE_GBUFFER_RUNS=1|verify|ab:<n>` — серии Phase 5 для G-буфера

- Лидер серии — draw `0x1a1770` с обходом SRT VS. Член серии может отличаться группами PsUserData и StencilRef.
- Если обход VS или PS читал изменившийся регистр, он повторяется (`RedecodeStage`). Член серии получает собственные
  константные буферы PS и собственный flat (`member_flat`), если тот отличается за пределами 16 регистров.
- Собственный stencil reference члена передаётся на поток 2 через `Executor::SetRunStencilRef` (динамическое состояние
  Vulkan).
- Изображения и сэмплеры PS должны совпадать, иначе отказ 13. Буферы могут отличаться, только если это константы самого
  draw, только для чтения, иначе отказ 14.
- С зондом материала член серии с `kMaterialChanged` получает отказ 16 до повторного обхода.
- `ab:<n>`: серии G-буфера только в нечётных блоках по n кадров (A/B изображения).

## 5. Результаты механизмов [E]

### 5.1 Повторное использование результата обхода без повторного обхода — 0 попаданий

Первый вариант `SSPC_CITY_ENGINE_RESOURCES` брал результат обхода предыдущего draw, если регистры, которые читал обход,
не изменились. Попаданий — **0**: 100 % отказов по причине «регистр, прочитанный обходом, изменился». Причина в §2: CUE
копирует таблицу стадии в новый блок кольца кадра при каждом коммите. Поэтому механизм переделан на повторный обход
с новыми регистрами (§3.2).

### 5.2 `SSPC_CITY_ENGINE_RESOURCES=1` — корректно, поток 1 не сокращает

- verify (`p6_ver_res2`): 4,95 млн draw подготовлены обоими путями, **0 расхождений**. Повторных обходов: VS 3,6 млн,
  PS 2,7 млн. Отказов по ключу — 0,85 млн.
- Диагностика (`d6B` против `d6A`): шаблон принял 3,23 млн draw G-буфера по 2,60 мкс и 1,45 млн draw мешей по 3,73 мкс.
  Но оставшиеся полные подготовки подорожали: G-буфер 3,87 → 6,20 мкс, меши 3,76 → 4,57 мкс. Сумма подготовок —
  11,8 мс на кадр против 11,0 мс у A.
- Почему: шаблон забирает draw с той же программой и другими user data. Фронтенд и так готовит их недорого: память
  стадии P4.7 и путь «другие user data» без поиска программы. Дорогие подготовки со сменой программы остаются — «другие
  входы» 21,2 → 21,6 млн. Повторный обход SRT стоит почти столько же, сколько полная подготовка такого draw: обход и
  чтение памяти — основная её часть, и шаблон их не убирает.

### 5.3 `SSPC_CITY_ENGINE_GBUFFER_RUNS=1` — серии G-буфера

- verify (`p6_ver_g3`, затем `p6_ver_mat` с зондом материала): **21,6 млн и 23,1 млн членов серий, 0 расхождений**.
- Без подсказки о материале (`d6C`): 2,03 млн членов по 1,79 мкс и **1,95 млн отказанных попыток по 2,11 мкс**. Попытка
  повторно обходила PS и только потом находила другие изображения (отказ 13, 1,22 млн) или другой ключ (отказ 12,
  0,46 млн). Выигрыш съеден.
- Подсказка `kMaterialChanged` (`p6_ver_mat`, verify — отказа не делает, только считает): помечено 1,95 млн попыток
  членства, из них присоединились бы всё равно 0,32 млн (17 %). То есть 83 % пометок — действительно другой набор
  дескрипторов PS. С подсказкой (`d6C2`): **отказы 12 и 13 — 0**, отказанная попытка стоит 0,06 мкс,
  член серии — 1,38 мкс.

## 11. Отклонено и ограничения

- Повторное использование результата обхода без повторного обхода — 0 попаданий (§5.1).
- `SSPC_CITY_ENGINE_RESOURCES` — корректен, выигрыша нет (§5.2): он заменяет дешёвые подготовки фронтенда почти такими
  же по цене.
