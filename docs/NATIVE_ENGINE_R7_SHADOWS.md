## 2. S1: ручная реконструкция цикла теней

### 2.1 Что написано руками

`src/native_engine/reconstructed/shadow_casters.{h,cpp}` — наш C++ (не перевод P-code):

| Функция | Что делает | Как написано |
|---|---|---|
| `0x43d590` Shadow::CastersLoop | обходит отсортированные видимые объекты одного каскада: отбрасывание по качеству (ГПСЧ `0x612110`, порог `[0xda08d0 + q*0x14]`), смена материала (`0x448640`), константы объекта/камеры (`0x11c890`/`0x11cde0` + копия в DCB и привязка в 2 стадии), параметры (`0x450460`/`0x451290`/`0x451700`), draw (`0x1a1960`) либо группировка экземпляров (ключ `^` первый `< 0x10000`), записи экземпляров 0x48 байт (4 строки объект×VP каскада + 8 нулевых байт) в кадровом скретче `0x1f0870`, draw группы `0x43d480` | вручную, вызовы через таблицу; FP строк — `{vex3}` asm с порядком операндов оригинала (как `ObjectConstants::ProjectRow`) |
| `0x43d480` Shadow::InstancedDraw | `0x120280`, V# записей (`0x61e260`, stride 0x48), привязка в стадию `0x27530(0)` слотом `pass[0x121]`, вершинные буферы меша, `NUM_INSTANCES`, `VGT_PRIMITIVE_TYPE=4`, `INDEX_TYPE=0`, коммит CUE, `DrawIndex` | вручную |

Не воспроизводятся только загрузки-предвыборки (`0x43e000..0x43e04c`: результат идёт лишь в `nop [reg]`).

Включение: `SSPC_NATIVE_ENGINE=verify|guarded|native`, `SSPC_NATIVE_ENGINE_FUNCS=shadow_casters_loop,shadow_instanced_draw`
и `SSPC_R7_SHADOWS_IMPL=hand` (или просто без `SSPC_NATIVE_ENGINE_RECOMP`). `SSPC_R7_SHADOWS_IMPL=recomp` — прежний
recomp R6. `0x43d480` ставится только под входной пробой CITY-OPT (как в R6, `FindEntryProbe`), второго jump нет.

## 3. NativeDrawCommand для `0x43d480`

`src/native_engine/r7/shadows/shadow_draw_command.{h,cpp}`:

```cpp
struct ShadowDrawInputs { u64 records; u32 record_stride = 0x48; u32 instances; u32 instance_slot;
                          u64 vertex_table; u32 vertex_buffers; };
void BuildInstancedDraw(u64 module_base, u64 pass, u64 r, u64 records, u64 n, u64 mesh,
                        NativeRenderContext& ctx, NativeDrawCommand& cmd, ShadowDrawInputs& inputs);
std::string CheckAgainstTrace(const NativeRenderContext&, const NativeDrawCommand&, const ShadowDrawInputs&,
                              const STrace::Trace& original_calls);
```

`BuildInstancedDraw` вызывается на входе `0x43d480` (до любой работы) и заполняет: `ctx` (r, CUE `r+0x128`, DCB
`r+8`, проход), `cmd` (producer `Shadows`, fn `ShadowInstanced` = 0x43d480, indexed, `index_count=[mesh+0x68]`,
`index_base=[mesh+0x58]`, `run_tag = Source::Shadow` (2), `state.prim = 4`, `state.index_size = 0`,
`state.num_instances = (u32)n`, `resources.cue`) и `inputs` — то, чего в контракте R7.0 нет (буфер записей экземпляров
с шагом 0x48, слот VS `pass[0x121]`, таблица вершинных буферов меша). `CheckAgainstTrace` проверяет 9 вызовов
оригинала по порядку и аргументам плюс V# записей (база 44 бита, stride, num_records).

Проверка: офлайн 2 000 draw, 0 различий (и неправильная команда ловится: +1 экземпляр, сдвиг базы); в игре
в режиме verify каждая сверка `0x43d480` сопровождается проверкой команды — **16 777 216 проверок, 0 расхождений**.
Submit команды не используется (R7.0 `Submit` — заглушка Off/Fallback), путь отрисовки остаётся оригинальным.

## 4. S2: `0x450460`, виды 0x10 и 0xa с объектом

### 4.1 Что делают ветки [A, Ghidra — своя копия `E:\research\r7\shadows\ghidra`]

`0x450460(records, block, atlas, view, table, buffers, owner)`: до 4 записей (`[records]` — счётчик, виды `+8`,
индексы `+0x18`), 18 видов через таблицу `0xaad7c0`, запись в блок `R+0xda18` (0x100 float + грязный байт `+0x404`)
через `0x11e5d0`. Поле слота по виду (смещение u16 в записях): 1/2/5→0x28, 0/3→0x2a, 4→0x2c, 7→0x2e, 6→0x30,
9→0x32, 0xa→0x36, 0xc→0x38, 0xd→0x3a, 0xe→0x3c, 0xf→0x3e, 0x10→0x40, 0x11→0x42; 8/0xb — без записи.

- **Вид 0x10** → `0x4502e0(n = (int)table[i], use_owner = table[i+1] > 0, owner[0x11], &4 float)`: ячейка листа
  спрайтов. `0x290380` — значения по умолчанию, `0x28fa30(0x1d1faa0, &rec)` под pthread-мьютексом объекта
  (`+0x20`; инициализация мьютекса и condvar при `[+0x30] == 0`) копирует текущую 32-байтную запись
  (`+0x230 + [+0x270]*0x20`: столбцы `+8`, строки `+0xc`, T# `+0x18`); затем `n % (cols*rows)`, деления, при T#
  — полутексельная поправка из ширины/высоты (`dword2` биты 13:0 / 27:14) и множитель 0.5625. Пишет 4 float.
- **Вид 0xa с объектом** (`buffers+0x88 != 0`): виртуальный геттер `[vtable+0x28]` (тип), ветка при
  `type − 5 < 0x46`: `0x4740c0(obj[5], 0xe4e35609ac35b83a)` (кость по хешу; при `[skel+0x190] == 0` → −1, иначе
  `0x785b0 → 0x6b860`), `0x476ed0` (родитель из таблицы short), обратная 3×3 родителя (`vrcpps` + шаг Ньютона,
  `vhaddps`) × перенос; результат ×0.01 → 1 float. Без объекта или вне диапазона типа — 0.0.

### 4.2 Реальные условия в игре [E]

`SSPC_R7_SHADOWS_PARAMS_CENSUS=1` / `SSPC_R7_SHADOWS_PARAMS_CHECK=<recomp.dll>` в ручном цикле (место вызова
`0x450460`, только живые вызовы): `r7s_hand_guarded_stats_params`, город, 150 с:

| Показатель | Значение |
|---|---|
| вызовов `0x450460` из цикла теней | 2 254 197 |
| разных блоков записей (`pass+0x90`) | 45 |
| записей (`[pass+0x90] > 0`) | **0** — у всех 45 проходов теней счётчик ≤ 0 |
| виды 0x10 / 0xa (с объектом и без) | 0 / 0 |
| сверено с `recomp_450460` (двойной прогон, результат оригинала остаётся) | 2 254 197, **0 различий**, 0 непроверенных |

Вывод: **в теневом движке ветки 0x10 и 0xa недостижимы** — проходы теней не несут записей параметров, `0x450460`
выходит на первой проверке (`cmp [rdi],0; jle`). Это согласуется с кодом цикла: в ветке экземпляров сам
`0x43d590` вызывает `0x451290` только при `[pass+0x90] > 0`. Ветки 0x10/0xa реальны для других вызывающих
`0x450460` (`0x19cf20`, `0x1a2030`, `0x46ca80`, `0x561810` — зона G-буфера/других проходов, не R7-S).

### 4.3 Офлайн-тест веток [E]

`r7_shadows_tests.cpp`, `GapDifferential`: `recomp_450460` против клона eboot `0x450460` на сгенерированных случаях
с видами 0x10 / 0xa / 0xb / −1. `0x4502e0`, `0x28fa30`, `0x290380`, `0x4740c0`, `0x476ed0` — настоящий код eboot
с обеих сторон; четыре импорта pthread (`MutexInit 0xd9e1d0`, `CondInit 0xd9e1c0`, `Lock 0xd9e1d8`,
`Unlock 0xd9e1e0` — слоты GOT) — считающие заглушки; глобальный лист `0x1d1faa0` генерируется (столбцы/строки
1..8, T# или нет, флаг инициализации 0/1) и восстанавливается; геттер — хост-функция с типом случая (0, 4, 5, 6,
0x20, 0x49..0x4c, случайные). Сравниваются: блок (с грязным байтом), лист после вызова, неизменность входов,
баланс lock/unlock, число вызовов lock/init/геттера.

|---|---|---|---|---|---|
| 0x1fbf (хост) | 100 000 | 39 794 | 29 855 | 13 150 | 0 |
| 0x9fc0 | 20 000 | 7 916 | 5 962 | 2 649 | 0 |
| 0x7f80 | 20 000 | 7 932 | 6 010 | 2 689 | 0 |
| 0x3f80 | 20 000 | 8 042 | 6 012 | 2 657 | 0 |
| 0x5f80 | 20 000 | 7 986 | 6 007 | 2 686 | 0 |

Не покрыто офлайн: путь хеш-поиска кости `0x785b0 → 0x6b860` (в тесте `[skel+0x190] = 0`, индекс −1) — его код
вызывается и у оригинала, и у recomp как внешний (`call_target`), т.е. переводом `0x450460` не затрагивается.

Статус `recomp_450460`: OFFLINE_VERIFIED на всех 18 видах (R6-S: все, кроме 0x10 и 0xa-с-объектом; R7-S: эти
два). В игре из теневого цикла — проверен на 2,25 млн вызовов, но все они без записей; **игровой проверки веток
0x10/0xa нет и в теневом движке быть не может** (недостижимы). Полной реконструкцией `0x450460` это не называю:
ветки проверены только офлайн.
